Clase 04/05 — Sistemas Operativos

RHEL 9

Parte 1 — Instalar Gemini CLI

Instalamos Node.js 20, Gemini CLI y autenticamos con nuestra cuenta Google. Es el punto de partida para controlar el servidor con lenguaje natural.

1

Prerequisito Node.js 20

Gemini CLI requiere Node.js 20 o superior. El repositorio base de RHEL 9 trae Node.js 16, por lo que hay que habilitar explícitamente el módulo correcto antes de instalar.

Pasos (máquina nueva):
1. Habilitar el stream de Node.js 20
2. Instalar con dnf

Validación: node --version debe mostrar v20.x.x — si muestra v16 o "command not found", el módulo no se habilitó correctamente.
bash — 80x24
[ec2-user@ip ~]$ sudo dnf module enable nodejs:20 -y Dependencies resolved. Complete! [ec2-user@ip ~]$ sudo dnf install nodejs -y Installing: nodejs 20.18.1 appstream Complete! # Validacion [ec2-user@ip ~]$ node --version v20.18.1 [ec2-user@ip ~]$ npm --version 10.8.2
2

Instalar Gemini CLI

Con Node.js 20 listo, instalamos Gemini CLI de forma global. El sudo es obligatorio porque la instalación escribe en /usr/local/lib/, que pertenece a root.

Comando:
sudo npm install -g @google/gemini-cli

El flag -g instala el ejecutable en /usr/local/bin/gemini, que ya está en el PATH de todos los usuarios.

Validación:
gemini --version → 0.1.x
which gemini → /usr/local/bin/gemini
bash — 80x24
[ec2-user@ip ~]$ sudo npm install -g @google/gemini-cli npm warn deprecated inflight@1.0.6 added 247 packages in 52s # Validacion [ec2-user@ip ~]$ gemini --version 0.1.7 [ec2-user@ip ~]$ which gemini /usr/local/bin/gemini [ec2-user@ip ~]$ ls -la /usr/local/bin/gemini -rwxr-xr-x. 1 root root 312 /usr/local/bin/gemini
3

Primer uso y autenticación

La primera vez que ejecutas gemini, solicita autenticación con una cuenta Google. El flujo es:

1. Ejecutar gemini en el servidor
2. Gemini muestra un URL de autenticación
3. Abrir ese URL en el navegador de tu PC (no en el servidor)
4. Iniciar sesión con tu cuenta Google
5. Copiar el código de autorización y pegarlo en la terminal

Las credenciales se guardan en ~/.config/gemini/ para sesiones futuras — no hay que autenticarse de nuevo.

Validación: después de autenticarte, escribe hola en el prompt de Gemini. Si responde en texto, la autenticación fue exitosa. Escribe /quit para salir.
bash — 80x24
[ec2-user@ip ~]$ gemini ╔══════════════════════════════════════════╗ ║ Welcome to Gemini CLI ║ ╚══════════════════════════════════════════╝ To authenticate, open this URL in your browser: https://accounts.google.com/o/oauth2/auth?... Enter the authorization code: 4/0AX4XfW... Authenticated successfully. Ready. Type your message below. # Validacion: escribe hola > hola Hola! Estoy listo para ayudarte a administrar este servidor. > /quit [ec2-user@ip ~]$

Parte 2 — Prompt 1
Config inicial

Usamos Gemini para dejar el servidor actualizado y configurado: hostname, zona horaria, firewall y servicios innecesarios deshabilitados.

4

Prompt — configuración inicial

Copia y pega este prompt en Gemini. Reemplaza [TU_HOSTNAME] por el nombre que le pusiste a tu instancia en AWS.

Cubre la actualización completa del servidor, configuración base, firewall, deshabilitar servicios innecesarios y restringir Gemini solo a ec2-user.

Parte 4 — Prompt 3
Hardening

Auditamos el servidor completo: actualizaciones, firewall, puertos, servicios y SSH. Gemini revisa cada punto e indica qué está bien y qué falta mejorar.

6

Prompt — auditoría hardening

Auditamos y aplicamos el hardening completo del servidor. Primero Gemini revisa el estado actual, luego aplica las correcciones de SSH y entrega un resumen final.

Validación — resultado esperado al finalizar:
sudo dnf check-update --security → 0 paquetes pendientes
sudo firewall-cmd --list-services → ssh
sudo ss -tlnp → solo puerto 22
sudo sshd -T | grep permitrootlogin → no
sudo sshd -T | grep passwordauthentication → no
sudo sshd -T | grep allowusers → ec2-user
Prompt — pegar en Gemini
> Eres un administrador de sistemas experto en RHEL 9. Vamos a aplicar el hardening de este servidor. Dame el plan completo primero sin ejecutar nada. Los pasos deben cubrir: 1. Revisar actualizaciones de seguridad pendientes (dnf check-update --security) 2. Verificar estado del firewall y servicios permitidos (firewall-cmd --list-all) 3. Revisar puertos en escucha y proceso dueno de cada uno (ss -tlnp) 4. Revisar servicios en ejecucion innecesarios (systemctl list-units --state=running) 5. Aplicar hardening SSH en /etc/ssh/sshd_config: PermitRootLogin no PasswordAuthentication no AllowUsers ec2-user MaxAuthTries 3 ClientAliveInterval 300 6. Verificar con sshd -T que los cambios aplicaron 7. Reiniciar sshd y confirmar que el servicio esta activo 8. Resumen final: que esta bien y que se corrigio Recuerda: plan primero, ejecucion con mi aprobacion en cada paso.

Parte 5 — Prompt 4
Apache y sitio web

Instalamos Apache HTTP Server, abrimos el puerto 80 en el firewall y levantamos una página web personalizada accesible desde el navegador.

7

Prompt — Apache y sitio web

Instalamos httpd (Apache), lo habilitamos para que arranque automáticamente y creamos una página de inicio personalizada.

Para acceder desde el navegador necesitas la IP pública de la instancia. Encuéntrala con:
curl -s http://169.254.169.254/latest/meta-data/public-ipv4

En el navegador escribe: http://[IP_PUBLICA]

Validación al finalizar:
sudo systemctl is-active httpd → active
sudo firewall-cmd --list-services → http ssh
curl http://localhost → responde con HTML
Navegador → http://[IP_PUBLICA] → página visible
Prompt — pegar en Gemini
> Eres un administrador de sistemas experto en RHEL 9. Necesito instalar Apache y levantar un sitio web. Dame el plan completo primero sin ejecutar nada: 1. Instalar el paquete httpd con dnf 2. Habilitar e iniciar el servicio httpd con systemctl (que arranque automaticamente al reiniciar) 3. Abrir el puerto HTTP (80) en el firewall de forma permanente y recargar firewalld 4. Crear una pagina de inicio en /var/www/html/index.html con el nombre del servidor, la fecha actual y el nombre del administrador (ec2-user) 5. Verificar que el servicio responde: curl http://localhost 6. Obtener la IP publica de la instancia y mostrarla para acceder desde el navegador Recuerda: plan primero, ejecucion paso a paso con mi aprobacion.

¿Qué es un diagrama de flujo?
Un diagrama de flujo es una representation gráfica de un algoritmo o proceso. Usa símbolos estandarizados para mostrar el flujo de control paso a paso.
Objetivo: Visualizar la lógica de un programa antes de codificarlo, facilitando la comprensión y comunicación de ideas.
Ventajas:
• Fácil de entender visualmente
• Ayuda a detectar errores de lógica
• Estándar en la industria
• Útil para documentar procesos
Analogía
Un diagrama de flujo es como un mapa de tu algoritmo
Así como un mapa muestra caminos y destinos, un diagrama de flujo muestra decisiones y acciones que sigue tu programa.
Inicio → Pasos → Decisiones → Fin
2a
Símbolos básicos
Óvalo / Elipse
Representa el INICIO y el FIN del diagrama. Siempre uno al inicio y otro al fin.
Rectángulo
Representa un PROCESO o acción. Ejemplo: asignar una variable, hacer un cálculo.
Rombo / Diamante
Representa una DECISIÓN o condición. Sale "Sí" o "No" según la condición.
Paralelogramo
Representa ENTRADA/SALIDA de datos. Ejemplo: Leer un valor, Escribir un resultado.
2b
Elementos de control
Flechas / Líneas de flujo
Conectan los símbolos y muestran la dirección del flujo. Siempre apuntan hacia abajo o a la derecha.
→ Flujo normal
Entre procesos
Etiquetas en flechas
En decisiones, las flechas se etiquetan con "Sí" o "No" (o "Verdadero"/"Falso").
✓ Sí
✗ No
Dirección del flujo: El diagrama se lee de arriba hacia abajo, de izquierda a derecha. Nunca hacia atrás (esto causa confusión).
Reglas básicas:
• Cada símbolo tiene una entrada y una salida
• Excepto Inicio (sin entrada) y Fin (sin salida)
• Las decisiones tienen dos salidas (Sí/No)
• Las flechas nunca se cruzan

Ejemplo práctico
Pseudocódigo
Proceso VerificarNota

    Definir nota Como Real
    Escribir "Tu nota:"
    Leer nota

    Si nota >= 4.0 Entonces
        Escribir "Aprobado"
    SiNo
        Escribir "Reprobado"
    FinSi

FinProceso

Buenas prácticas
✓ Correcto
• Flujo de arriba hacia abajo
• Etiquetas claras en los símbolos
• Una línea de entrada y salida
• Decisiones con "Sí" y "No"
• Símbolos de igual tamaño
✗ Incorrecto
• Flujo sin dirección clara
• Símbolos sin etiquetar
• Líneas cruzadas
• Múltiples entradas/salidas
• Símbolos mal usados
Nivel de detalle: El diagrama debe estar entre lo muy simple y lo muy complejo. Normalmente, cada símbolo de proceso representa 2-3 líneas de pseudocódigo.
Estándares
• ISO 5807 (norma internacional)
• PSeInt y herramientas usan estos símbolos
• Usados en industria y academia
• Universales en la programación
5
Ejercicio: cajero
Proceso Cajero

  // Bloque 1: verificar tarjeta
  Repetir
    Escribir "Ingrese su tarjeta"
    Leer tarjeta
    Si tarjeta <> "1234-5678" Entonces
      Escribir "Tarjeta invalida, intente de nuevo"
    FinSi
  Hasta Que tarjeta = "1234-5678"

  // Bloque 2: verificar PIN
  Repetir
    Escribir "Ingrese su PIN"
    Leer pin
    Si pin <> 9876 Entonces
      Escribir "PIN incorrecto"
    FinSi
  Hasta Que pin = 9876

  // Bloque 3: verificar saldo
  saldo <- 500000
  Repetir
    Escribir "Ingrese monto a retirar"
    Leer monto
    Si monto > saldo Entonces
      Escribir "Saldo insuficiente"
    FinSi
  Hasta Que monto <= saldo

  Escribir "Retiro de $", monto, " realizado"
  saldo <- saldo - monto
  Escribir "Nuevo saldo: $", saldo

FinProceso

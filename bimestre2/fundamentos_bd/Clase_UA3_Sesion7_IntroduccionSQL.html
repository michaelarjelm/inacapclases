En la UA2 modelamos bases de datos en papel. Hoy esos modelos cobran vida. Veamos el puente.

Contexto
01 - El puente · Lo que ya tienes
Lo que dibujaste,
ahora lo escribes

En la Unidad 2 terminaste con el modelo físico de la biblioteca: tablas con sus columnas, tipos de dato (NUMBER, VARCHAR2...), claves primarias y foráneas. Pero todo eso estaba dibujado en un diagrama. La base de datos todavía no existe.

Ese dibujo es el plano. Hoy aprendemos a levantarlo: convertir cada caja del diagrama en una tabla real dentro de Oracle, que guarda datos de verdad. El idioma para hacerlo se llama SQL.

💡
La analogía del plano y la casa

El modelo de la UA2 es el plano del arquitecto: dice cuántas piezas hay y cómo se conectan. SQL es la construcción: con él levantas las paredes (tablas), traes los muebles (datos) y después recorres la casa buscando cosas (consultas). Mismo plano, ahora habitable.

02 - Concepto
Bloque 02
Qué es
SQL

El idioma universal de las bases de datos relacionales. Más simple de lo que suena.

Concepto
02 - Qué es · Definición
El idioma para
dar órdenes

SQL significa Structured Query Language (Lenguaje de Consulta Estructurado). Es el idioma con el que le das órdenes a una base de datos relacional: "créame esta tabla", "guarda este dato", "muéstrame los socios de Santiago".

Lo bueno de SQLQué significa para ti
Es casi inglésLas órdenes se leen como frases: SELECT nombre FROM socios = "selecciona nombre de socios".
Es un estándarEl mismo SQL (con pequeñas diferencias) sirve en Oracle, MySQL, PostgreSQL, SQL Server... Lo aprendes una vez.
Le dices QUÉ, no CÓMOPides el resultado que quieres; la base se encarga de cómo buscarlo. Tú no programas la búsqueda.
✓
En nuestro curso

Usaremos SQL sobre Oracle, el motor que instalamos. Pero lo que aprendas hoy te sirve en casi cualquier base de datos del mundo laboral.

Concepto
02 - Qué es · Sintaxis general
Las reglas
del idioma

Antes de escribir nada, cuatro reglas que valen para toda sentencia SQL. Con esto ya puedes leer cualquier instrucción:

1. Termina en punto y coma

Cada orden completa termina con ;. Es el "punto final" que le dice a la base "ejecuta hasta aquí".

2. Las palabras clave en MAYÚSCULAS

SQL no distingue mayúsculas, pero por convención escribimos SELECT, FROM, WHERE en mayúsculas para que se lean fácil.

3. El texto va entre comillas simples

Los valores de texto se escriben entre 'comillas simples': 'Ana Gomez'. Los números van sin comillas.

4. Los espacios y saltos dan igual

Puedes escribir todo en una línea o repartido en varias. Se usa para que quede ordenado y legible.

✓
Léelo en voz alta

Si lees SELECT titulo FROM libros; como "selecciona título, de libros", ya entendiste la sintaxis. SQL está hecho para leerse así.

SQL no es una sola cosa: son grupos de órdenes según para qué sirven. Este es el mapa de toda la unidad.

El mapa
03 - Familias · Las 4 que usaremos
Cuatro grupos,
cuatro trabajos

Toda orden de SQL pertenece a una familia, según qué trabajo hace. Memoriza estas cuatro: son el esqueleto de la Unidad 3.

DDL
Definición · la estructura
Construye y modifica las tablas (el esqueleto). Define cómo es la base, no qué datos tiene.
CREATEALTERDROP
DML
Manipulación · los datos
Mete, cambia y borra los datos dentro de las tablas. Los muebles que entran y salen.
INSERTUPDATEDELETE
DQL
Consulta · las preguntas
Le hace preguntas a la base y trae respuestas. Es la que más vas a usar en la vida real.
SELECT
TCL
Transacciones · confirmar
Decide si los cambios se guardan de verdad o se deshacen. Tu botón de "confirmar" y "deshacer".
COMMITROLLBACK
💡
Existe una quinta: DCL

La DCL (Control de Datos: GRANT, REVOKE) maneja permisos: quién puede ver o tocar qué. La mencionamos cuando hablemos de seguridad, pero las cuatro de arriba son las protagonistas.

04 - Documentación · No se memoriza, se consulta
Dónde mirar
cuando dudas

Nadie se sabe SQL de memoria, ni los profesionales con años de experiencia. Lo que sí saben es dónde buscar la sintaxis exacta. Esa es una habilidad que evaluamos: saber consultar la documentación.

La fuente oficial

La documentación de Oracle es la verdad final. Busca "Oracle Database SQL Language Reference". Ahí está cada comando con su forma exacta y ejemplos.

docs.oracle.com

Cómo usarla

Cuando no recuerdes cómo se escribe algo (por ejemplo CREATE TABLE), búscalo, copia la estructura y adáptala a tu caso. Eso no es hacer trampa: es trabajar bien.

✓
Regla de oro del programador

No se trata de saberlo todo, se trata de saber buscarlo. Memoriza los conceptos (las 4 familias, para qué sirve cada una); la sintaxis exacta siempre la puedes consultar.

05 - Laboratorio · El saludo
Hola, base
de datos

Con SQL Developer abierto y conectado, escribe esta orden en la hoja y ejecútala con Ctrl + Enter:

SELECT 'Hola, base de datos' AS saludo FROM dual;

La base te responde con una tabla de una sola fila:

SALUDO
Hola, base de datos
💡
¿Qué es dual?

dual es una tablita de prueba que Oracle trae siempre, con una sola fila. Sirve justo para esto: probar una orden rápida sin necesitar una tabla propia. La usamos para "saludar" y comprobar que todo funciona.

Demo
05 - Laboratorio · Un adelanto
Una tabla,
en vivo

Solo para que veas a dónde vamos la próxima clase: así se crea una tabla y se guarda un dato. No te preocupes por entender cada parte hoy, es un adelanto del DDL y el DML:

-- DDL: creo la estructura (lo vemos el 02/07)
CREATE TABLE prueba (id NUMBER, nombre VARCHAR2(50));
-- DML: guardo un dato (lo vemos el 08/07)
INSERT INTO prueba VALUES (1, 'Ana');
-- DQL: le pregunto qué guardó
SELECT * FROM prueba;
✓
Fíjate en el patrón

Ahí están tres de las cuatro familias en seis líneas: creas (DDL), guardas (DML) y preguntas (DQL). Toda la Unidad 3 es repetir y profundizar este ciclo. Hoy solo querías verlo una vez.

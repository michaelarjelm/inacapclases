01 - SELECT · Pedir columnas
Elige qué
quieres ver

El SELECT tiene dos partes mínimas: qué columnas quieres y de qué tabla. El * significa "todas las columnas".

ConsultaQué devuelve
SELECT * FROM libro;Todas las columnas, todas las filas.
SELECT titulo, copias FROM libro;Solo esas dos columnas.
SELECT titulo AS nombre FROM libro;Renombra la columna en el resultado (alias).
SELECT DISTINCT id_socio FROM prestamo;Valores sin repetir.
💡
El alias es cosmético

AS solo cambia el título de la columna en la respuesta; no toca la tabla. Sirve para que el resultado se lea mejor. La palabra AS es opcional, pero escribirla se entiende más.

02 - WHERE · Filtrar filas
Solo las filas
que cumplen

Si SELECT elige columnas, WHERE elige filas: se queda solo con las que cumplen una condición.

SELECT titulo, copias FROM libro WHERE copias > 2;
Operadores
  • = igual
  • <> distinto
  • > < >= <=
Unir condiciones
  • AND: deben cumplirse las dos
  • OR: basta con una
⚠
El texto va entre comillas simples

WHERE nombre = 'Ana Perez'. Y ojo: Oracle distingue mayúsculas de minúsculas en el texto, 'ana perez' no es lo mismo que 'Ana Perez'.

20:30 · 20 min Teclado 2
Ahora tú:
filtra

-- Un socio exacto

-- Dos condiciones a la vez

-- Una u otra
SELECT titulo, copias FROM libro WHERE copias = 0 OR copias >= 4;

03 - Filtros especiales · Cuatro herramientas
Filtrar con
precisión

Cuatro operadores que resuelven casos que = y > no cubren bien:

OperadorPara qué sirve
LIKE 'C%'Buscar por patrón de texto. % = cualquier cosa, _ = un carácter.
BETWEEN a AND bRango, incluye los dos extremos. Sirve con números y fechas.
IN (1, 2, 3)Pertenece a una lista de valores. Reemplaza muchos OR.
IS NULLLa columna está vacía (sin dato). Su opuesto: IS NOT NULL.
⚠
NULL no se compara con =

WHERE email = NULL nunca devuelve filas, aunque haya vacíos. El vacío es especial: se pregunta con IS NULL, jamás con =. Es el error más típico de este bloque.

Ahora tú: los
cuatro filtros

Uno por cada operador. Fíjate en qué filas de la semilla caza cada uno:

-- LIKE: títulos que empiezan con C

-- BETWEEN: libros con 1 a 3 copias
SELECT titulo, copias FROM libro WHERE copias BETWEEN 1 AND 3;
-- IN: préstamos de los socios 1 o 2
SELECT * FROM prestamo WHERE id_socio IN (1, 2);
-- IS NULL: socios sin email
SELECT nombre FROM socio WHERE email IS NULL;

21:30 · 6 min Pildora 4
04 - ORDER BY · Ordenar el resultado
Ponlo en
orden

ORDER BY ordena las filas del resultado por una o más columnas. Va siempre al final de la consulta.

-- ASC = ascendente (es el valor por defecto)
SELECT titulo, copias FROM libro ORDER BY copias ASC;
-- DESC = descendente (de mayor a menor)
SELECT titulo, copias FROM libro ORDER BY copias DESC;
-- Dos criterios: primero copias, y empates por título
SELECT titulo, copias FROM libro ORDER BY copias DESC, titulo ASC;
💡
El orden de la sentencia importa

Siempre en esta secuencia: SELECT ... FROM ... WHERE ... ORDER BY. Si pones ORDER BY antes del WHERE, da error de sintaxis.

21:36 · 14 min Teclado 4
Ahora tú:
ordena

Combina lo de hoy: filtrar y ordenar en la misma consulta.

-- Socios en orden alfabético
SELECT nombre FROM socio ORDER BY nombre;
-- Préstamos del más reciente al más antiguo
SELECT * FROM prestamo ORDER BY fecha_prestamo DESC;
-- Solo los disponibles, del que más copias tiene al que menos
SELECT titulo, copias FROM libro WHERE copias > 0 ORDER BY copias DESC;

05 - JOIN · El pago del modelo (no entra en la ES3)
Cruzar dos
tablas

Un problema que arrastramos toda la clase: prestamo guarda id_socio = 1, no "Ana". El nombre vive en otra tabla. Para verlos juntos, hay que cruzar las dos tablas por su clave.

-- Antes: solo ids, sin nombres
SELECT * FROM prestamo; -- id_socio = 1 ... quién es?
-- JOIN: traer el nombre desde socio
SELECT prestamo.id_prestamo, socio.nombre
FROM prestamo
JOIN socio ON prestamo.id_socio = socio.id_socio;

El ON dice por dónde se pegan: la FK de prestamo coincide con la PK de socio. Para exactamente esto existían las claves foráneas desde la UA2. Cuando una columna se llama igual en las dos tablas, se antepone la tabla: prestamo.id_socio.

⚠
Esto NO entra en la ES3

La evaluación pide consultas de una tabla. El JOIN es un paso más, para que veas por qué modelaste con claves foráneas. Míralo con calma, sin presión de examen.

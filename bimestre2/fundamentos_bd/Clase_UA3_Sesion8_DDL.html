01 - CREATE · La anatomía
Una tabla
tiene forma

Crear una tabla es declarar sus columnas, el tipo de dato de cada una y una clave primaria que identifica cada fila sin repetirse.

CREATE TABLE socio (
id_socio NUMBER,
nombre VARCHAR2(50),
email VARCHAR2(80),
CONSTRAINT pk_socio PRIMARY KEY (id_socio)
);
NUMBER

Para números: identificadores, cantidades, dinero.

VARCHAR2(n)

Para texto de largo variable. La n es el máximo de caracteres.

DATE

Para fechas. Lo usaremos en PRESTAMO.

02 - Restricciones · Reglas por columna
La tabla se
defiende

Una restricción es una regla que la base hace cumplir sola. Si un dato la rompe, lo rechaza. Así los datos malos nunca entran.

RestricciónQué obliga
NOT NULLLa columna no puede quedar vacía.
UNIQUENo se puede repetir el valor (ej: un ISBN, un email).
CHECK (cond)El valor debe cumplir una condición (ej: copias >= 0).
DEFAULT valorSi no das dato, usa este por defecto.

Ahora tú:
crea LIBRO

Crea LIBRO usando las cuatro restricciones. Fíjate dónde va cada una:

CREATE TABLE libro (
id_libro NUMBER CONSTRAINT pk_libro PRIMARY KEY,
titulo VARCHAR2(120) NOT NULL,
isbn VARCHAR2(20) UNIQUE,
copias NUMBER DEFAULT 1 CHECK (copias >= 0)
);
⚠
Rompe la regla a propósito

Cuando termines, intenta INSERT INTO libro (id_libro, titulo, copias) VALUES (1, 'Test', -5); La base lo rechaza por el CHECK. Eso es una restricción trabajando. (El INSERT lo vemos formal el 08/07.)

03 - Integridad referencial · El corazón de hoy
Conectar
las tablas

Un préstamo pertenece a un socio y a un libro que ya existen. La clave foránea (FK) obliga a eso: no puedes prestar a un socio fantasma.

CONSTRAINT fk_prestamo_socio
FOREIGN KEY (id_socio) REFERENCES socio(id_socio)

Se lee: "la columna id_socio de PRESTAMO apunta a la id_socio de SOCIO". Esa flecha es la integridad referencial.

💡
Regla de oro del orden

Primero se crean las tablas a las que se apunta (SOCIO, LIBRO) y después la que apunta (PRESTAMO). No puedes referenciar una tabla que aún no existe.

21:12 · 23 min Teclado 3
Ahora tú:
crea PRESTAMO

La tabla que une todo. Dos claves foráneas y una fecha con valor por defecto:

CREATE TABLE prestamo (
id_prestamo NUMBER CONSTRAINT pk_prestamo PRIMARY KEY,
id_socio NUMBER NOT NULL,
id_libro NUMBER NOT NULL,
fecha_prestamo DATE DEFAULT SYSDATE,
CONSTRAINT fk_prestamo_socio FOREIGN KEY (id_socio) REFERENCES socio(id_socio),
CONSTRAINT fk_prestamo_libro FOREIGN KEY (id_libro) REFERENCES libro(id_libro)
);
✓
Comprueba la conexión

Con las tres tablas creadas, tu biblioteca ya tiene esqueleto completo. SYSDATE es la fecha de hoy: si no indicas fecha al prestar, Oracle la pone sola.

21:35 · 5 min Pildora 4
04 - ALTER y DROP · Cambiar y eliminar
Modificar
y borrar

Una tabla no queda congelada. ALTER la cambia; DROP la elimina completa.

-- Agregar una columna nueva
ALTER TABLE socio ADD (telefono VARCHAR2(15));
-- Cambiar el tipo o tamaño de una existente
ALTER TABLE socio MODIFY (email VARCHAR2(100));
-- Eliminar la tabla completa
DROP TABLE prestamo;
⚠
El orden importa al borrar

No puedes borrar SOCIO si PRESTAMO todavía la apunta. Primero se elimina la que tiene la FK (PRESTAMO), luego las padre. Es la regla de creación, al revés.

Ejercicio 12
Experto
Dominio · Tienda online · Nivel ES3
El jefe final

Diseña una tienda online completa desde cero: tres tablas conectadas, todas las restricciones que veas necesarias, en el orden correcto. Y al final, un ALTER.

Modelo E-COMMERCE
  1. CLIENTE: id, email (único, obligatorio), nombre (obligatorio), fecha de registro (por defecto hoy).
  2. PEDIDO: id, el cliente que lo hizo (FK), fecha (por defecto hoy), estado (por defecto 'PENDIENTE'), total (no negativo).
  3. DETALLE_PEDIDO: id, el pedido al que pertenece (FK), nombre del producto (obligatorio), cantidad (mayor que 0), precio unitario (mayor que 0).
  4. Después de crear todo: agrega a PEDIDO una columna descuento que solo acepte valores entre 0 y 100.
Ver solución
CREATE TABLE cliente (
id_cliente NUMBER CONSTRAINT pk_cliente PRIMARY KEY,
email VARCHAR2(100) NOT NULL UNIQUE,
nombre VARCHAR2(80) NOT NULL,
fecha_registro DATE DEFAULT SYSDATE);
CREATE TABLE pedido (
id_pedido NUMBER CONSTRAINT pk_pedido PRIMARY KEY,
id_cliente NUMBER NOT NULL,
fecha DATE DEFAULT SYSDATE,
estado VARCHAR2(20) DEFAULT 'PENDIENTE',
total NUMBER CHECK (total >= 0),
CONSTRAINT fk_pedido_cliente FOREIGN KEY (id_cliente) REFERENCES cliente(id_cliente));

nombre_producto VARCHAR2(100) NOT NULL,
cantidad NUMBER CHECK (cantidad > 0),

CONSTRAINT fk_detalle_pedido FOREIGN KEY (id_pedido) REFERENCES pedido(id_pedido));

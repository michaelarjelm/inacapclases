PARTE A: Definición de datos (DDL) - [28 puntos | Ítems 2 a 5 de la escala]

Creación de las cuatro tablas respetando las dependencias de clave foránea (primero las tablas maestras CLIENTE y PROVEEDOR, luego MEDICAMENTO que depende de PROVEEDOR, y por último VENTA que depende de CLIENTE y MEDICAMENTO). Se debe validar el uso correcto de restricciones de integridad (`NOT NULL`, `UNIQUE`, `DEFAULT`, `CHECK` y claves primarias/foráneas).

-- 1. Creación de tabla CLIENTE CREATE TABLE CLIENTE ( id_cliente NUMBER(10) CONSTRAINT pk_cliente PRIMARY KEY, nombre VARCHAR2(100) CONSTRAINT nn_cliente_nombre NOT NULL, rut VARCHAR2(12) CONSTRAINT nn_cliente_rut NOT NULL CONSTRAINT un_cliente_rut UNIQUE, telefono VARCHAR2(15) ); -- 2. Creación de tabla PROVEEDOR CREATE TABLE PROVEEDOR ( id_proveedor NUMBER(10) CONSTRAINT pk_proveedor PRIMARY KEY, nombre VARCHAR2(100) CONSTRAINT nn_proveedor_nombre NOT NULL, telefono VARCHAR2(15) CONSTRAINT nn_proveedor_telefono NOT NULL, ciudad VARCHAR2(50), activo VARCHAR2(1) DEFAULT 'S' CONSTRAINT ck_proveedor_activo CHECK (activo IN ('S', 'N')) ); -- 3. Creación de tabla MEDICAMENTO CREATE TABLE MEDICAMENTO ( id_medicamento NUMBER(10) CONSTRAINT pk_medicamento PRIMARY KEY, nombre VARCHAR2(50) CONSTRAINT nn_med_nombre NOT NULL, precio NUMBER(10) CONSTRAINT ck_med_precio CHECK (precio > 0), stock NUMBER(10) DEFAULT 0 CONSTRAINT ck_med_stock CHECK (stock >= 0), requiere_receta VARCHAR2(1) DEFAULT 'N' CONSTRAINT ck_med_receta CHECK (requiere_receta IN ('S', 'N')), id_proveedor NUMBER(10) CONSTRAINT nn_med_proveedor NOT NULL CONSTRAINT fk_med_proveedor REFERENCES PROVEEDOR(id_proveedor) ); -- 4. Creación de tabla VENTA CREATE TABLE VENTA ( id_venta NUMBER(10) CONSTRAINT pk_venta PRIMARY KEY, id_cliente NUMBER(10) CONSTRAINT nn_venta_cliente NOT NULL CONSTRAINT fk_venta_cliente REFERENCES CLIENTE(id_cliente), id_medicamento NUMBER(10) CONSTRAINT nn_venta_med NOT NULL CONSTRAINT fk_venta_med REFERENCES MEDICAMENTO(id_medicamento), cantidad NUMBER(10) CONSTRAINT nn_venta_cant NOT NULL CONSTRAINT ck_venta_cantidad CHECK (cantidad > 0), fecha DATE DEFAULT SYSDATE CONSTRAINT nn_venta_fecha NOT NULL );

Criterios de Puntaje (Parte A - Escala ítems 2 a 5):

  • Ítem 2 - PK y Tipos de Datos [7 pts]: Definición correcta de las 4 tablas con tipos lógicos (NUMBER para IDs/cantidades/precios, VARCHAR2 para nombres/RUTs/indicadores, DATE para fecha) y su clave primaria.
  • Ítem 3 - FK MEDICAMENTO → PROVEEDOR [7 pts]: Declaración correcta de la restricción referencial id_proveedor. Restar 3 puntos si se crea la FK pero no se declara NOT NULL, dado que la regla de negocio exige que el proveedor "debe existir".
  • Ítem 4 - FK VENTA → CLIENTE y MEDICAMENTO [7 pts]: Declaración correcta de ambas restricciones referenciales. Restar 3 puntos si se crean las llaves foráneas pero no se declaran NOT NULL ("ambos deben existir").
  • Ítem 5 - CHECK/NOT NULL/UNIQUE/DEFAULT [7 pts]: Validar que stock sea >= 0, precio > 0, cantidad > 0, requiere_receta y activo admitan solo 'S' o 'N', rut sea UNIQUE y NOT NULL, y los valores DEFAULT (stock, requiere_receta, activo, fecha) estén bien asignados.

PARTE D: Actualización y borrado (DML: UPDATE / DELETE) - [7 puntos | Ítem 8 de la escala]

Ejecución de cambios y operaciones selectivas sobre los datos agregados. Las modificaciones deben restringirse únicamente a las filas deseadas.

Criterios de Puntaje (Parte D - Escala ítem 8):

  • Ítem 8 - Modificaciones Selectivas [7 pts]: Validar que todos los `UPDATE` y `DELETE` tengan cláusulas `WHERE` precisas. Si un estudiante omite el `WHERE` en alguna de las sentencias y afecta a toda la tabla de manera irreversible, el puntaje de este ítem disminuye en 4 puntos. Se requiere el `COMMIT` final.

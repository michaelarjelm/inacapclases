01 — Server Manager
Bloque 01
Server
Manager

Es el panel de control del servidor. Desde aquí se gestiona todo: roles, servicios, eventos y configuración local. Lo primero que ves al conectarte por RDP.

Concepto
01 — Server Manager · Qué es
¿Qué es
Server Manager?

Server Manager es la herramienta central de administración de Windows Server. Se abre automáticamente al iniciar sesión y desde ella puedes:

  • Ver el estado general del servidor (CPU, RAM, eventos)
  • Agregar y quitar Roles (Active Directory, DNS, DHCP, IIS...)
  • Agregar y quitar Features (características del sistema)
  • Acceder a la configuración del servidor local
  • Gestionar servidores remotos desde un solo panel
💡
Todo pasa por aquí

Durante toda la unidad, la mayoría de las configuraciones que hagamos comenzarán desde Server Manager. Es el punto de partida obligatorio.

Orientación
01 — Server Manager · Interfaz
Las 4 áreas
principales

Al abrir Server Manager verás este panel. Identifica estas cuatro áreas antes de continuar:

  • Dashboard: resumen visual del estado del servidor. Alertas y accesos rápidos.
  • Local Server: configuración del servidor actual. Aquí cambiaremos el hostname, la IP y el firewall.
  • All Servers: lista de todos los servidores gestionados.
  • Manage (menú superior): agregar roles, features y servidores.
✓
Si Server Manager no se abre automáticamente

Búscalo en el menú Inicio o ejecuta servermanager.exe en el cuadro de búsqueda.

Orientación

02 — Hostname
Bloque 02
Cambiar el
hostname

El hostname es el nombre con el que el servidor se identifica en la red. AWS asigna uno genérico al crear la instancia. Vamos a cambiarlo por uno descriptivo.

Concepto
02 — Hostname · Por qué cambiarlo
¿Por qué importa
el nombre del servidor?

AWS asigna un hostname automático como EC2AMAZ-XXXXXXX. Ese nombre no tiene significado para nadie y dificulta identificar el servidor en redes con múltiples máquinas.

Un buen hostname describe el rol del servidor. Por ejemplo:

  • WinSRV-Manual — servidor Windows configurado manualmente
  • DC01-Empresa — primer controlador de dominio
  • WEB-Produccion — servidor web en producción
⚠
El servidor se reinicia al cambiar el nombre

Es obligatorio. El nuevo nombre solo toma efecto después del reinicio. La sesión RDP se cerrará y deberás volver a conectarte.

Pasos

03 — Idioma
Bloque 03
Cambiar el
idioma

Las VMs de Windows Server en AWS vienen en inglés. Antes de configurar cualquier otra cosa, es buena práctica cambiar el idioma del sistema a español para que todos los menús sean predecibles durante el trabajo.

Concepto
03 — Idioma · Por qué cambiarlo primero
¿Por qué cambiar
el idioma ahora?

Windows Server en AWS se despliega en inglés por defecto. Hay tres razones para cambiarlo antes de continuar con cualquier otra configuración:

  • Coherencia: todos los nombres de menú de esta lámina corresponden a la interfaz en español. Si tu servidor está en inglés, los pasos no coinciden.
  • Trabajo en equipo: si un compañero se conecta al mismo servidor, ve los mismos menús en el mismo idioma.
  • Documentación: los manuales y procedimientos que redactes serán consistentes con la interfaz que ven todos.
⚠
Requiere reinicio y puede tardar

El paquete de idioma pesa varios cientos de MB. La descarga depende del ancho de banda del laboratorio. El cambio de idioma de pantalla requiere cerrar sesión y volver a entrar.

💡
Idioma de interfaz vs. idioma del teclado

Son dos configuraciones independientes. Aquí cambiaremos el idioma de la interfaz (menús y ventanas). El idioma del teclado se configura por separado si es necesario.

04 — IP Fija
Bloque 04
IP privada
estática

Por defecto la NIC de Windows toma IP por DHCP. Si AWS reasigna la dirección, la configuración de red interna puede quedar inconsistente. La fijamos manualmente usando los datos del CIDR de la subred.

Concepto
04 — IP Estática · Qué necesitamos saber
Los datos que necesitas
antes de empezar

Para configurar la IP de forma estática necesitas cuatro valores. Todos se obtienen desde la consola de AWS sin salir de ella:

  • IP privada actual: la que AWS le asignó a tu instancia (ejemplo: 172.31.37.145). La usarás como IP fija.
  • CIDR de la subred: por ejemplo 172.31.32.0/20. De aquí sacas la máscara.
  • Gateway: es siempre la primera IP de la subred + 1. Para 172.31.32.0/20 el gateway es 172.31.32.1.
  • DNS preferido: 169.254.169.253 — el resolver de AWS. Lo usamos ahora porque el servicio DNS del servidor aún no está instalado.
  • DNS alternativo: 8.8.8.8 como respaldo.
💡
Máscara de red desde el prefijo CIDR

Los prefijos más comunes en AWS: /16 → 255.255.0.0  |  /20 → 255.255.240.0  |  /24 → 255.255.255.0.

⚠
El DNS cambia cuando instalemos AD DS

Este servidor será controlador de dominio. Una vez instalado el rol de AD DS + DNS, volveremos a las propiedades IPv4 y cambiaremos el DNS preferido a la IP privada del propio servidor. Por ahora usamos el resolver de AWS para tener internet durante la configuración.

⚠
No cambies la IP, solo la haces estática

Usa exactamente la misma IP que AWS ya le asignó. Si escribes otra IP que no está en el CIDR de la subred, el servidor pierde conectividad y ya no puedes conectarte por RDP.

Pasos
04 — IP Estática · Obtener datos desde AWS
Paso 1: recopilar los
datos desde AWS
Consola AWS → EC2 → Instances → selecciona tu instancia
1
En la pestaña Details de la instancia, anota Private IPv4 address
Ejemplo: 172.31.37.145. Esta dirección la usarás como IP estática.
2
Haz clic en el enlace del Subnet ID
Te lleva al panel de VPC donde verás el CIDR de la subred.
3
Anota el IPv4 CIDR de la subred
Ejemplo: 172.31.32.0/20. De aquí derivas la máscara y el gateway.
4
Calcula los cuatro valores que necesitas
IP estática: la misma Private IPv4 del paso 1
Máscara: según el prefijo del CIDR (para /20 → 255.255.240.0)
Gateway: dirección de red del CIDR + 1 (para 172.31.32.0/20 → 172.31.32.1)
DNS preferido: 169.254.169.253 (resolver de AWS — temporal hasta instalar AD DS)
DNS alternativo: 8.8.8.8

05 — Actualizaciones
Bloque 05
Actualizaciones
del sistema

Un servidor sin actualizar tiene vulnerabilidades conocidas. Actualizar es la acción de seguridad más básica y efectiva que existe.

Concepto
05 — Actualizaciones · Por qué es crítico
¿Por qué actualizar
el servidor?

La imagen de Windows Server que usas en AWS tiene una fecha de creación. Desde esa fecha, Microsoft ha publicado parches de seguridad que corrigen vulnerabilidades descubiertas. Si no actualizas, esas vulnerabilidades están expuestas.

  • Parches de seguridad: corrigen vulnerabilidades que podrían ser explotadas
  • Actualizaciones de funcionalidad: mejoran el rendimiento y estabilidad
  • Actualizaciones de definiciones: para Windows Defender
⚠
Puede demorar bastante

Si la imagen es antigua, pueden haber muchas actualizaciones pendientes. El proceso puede tardar entre 15 y 40 minutos. El servidor puede reiniciarse una o más veces.

06 — Firewall
Bloque 06
Firewall
de Windows

El firewall controla qué tráfico entra y sale del servidor. Una configuración correcta permite solo lo necesario y bloquea todo lo demás.

Concepto
06 — Firewall · Qué es y cómo funciona
Windows Defender
Firewall

Windows Defender Firewall es el firewall integrado de Windows Server. Controla el tráfico de red mediante reglas: cada regla define si un tipo de tráfico específico está permitido o bloqueado.

Hay dos tipos de reglas que usaremos:

  • Inbound rules (entrada): controlan el tráfico que llega al servidor. Por ejemplo, permitir que alguien se conecte al puerto 80 (HTTP).
  • Outbound rules (salida): controlan el tráfico que sale del servidor. Por defecto, casi todo está permitido.
⚠
Dos capas de firewall

En AWS tienes el Security Group (firewall de la nube) y el Windows Firewall (firewall del sistema operativo). Ambos deben permitir el tráfico para que funcione. Si uno bloquea, la conexión falla.

Orientación
06 — Firewall · Abrir la herramienta
Windows Firewall
with Advanced Security
Server Manager → Local Server → Windows Firewall (clic) → Advanced Settings

Al abrir Windows Firewall with Advanced Security verás tres secciones principales en el panel izquierdo:

  • Inbound Rules: reglas de tráfico entrante (las más importantes para nosotros)
  • Outbound Rules: reglas de tráfico saliente
  • Connection Security Rules: reglas de autenticación de conexiones
Pasos
06 — Firewall · Crear una regla de entrada
Crear una regla
de entrada (Inbound)

Como ejemplo práctico, crearemos una regla que permita tráfico HTTP (puerto 80). El mismo proceso aplica para cualquier otro puerto.

1
Clic derecho en Inbound Rules → New Rule...
Se abre el asistente de nueva regla.
2
Rule Type → selecciona Port → Next
Esta opción crea una regla basada en un número de puerto específico.
3
Protocol: TCP | Specific local ports: 80 → Next
Puerto 80 es HTTP. Para HTTPS sería 443. Para RDP sería 3389.
4
Action → Allow the connection → Next
Permite el tráfico que cumpla esta regla.
5
Profile → deja todos marcados (Domain, Private, Public) → Next
Aplica la regla en todos los perfiles de red.
6
Name: escribe HTTP-Puerto80 → Finish
La regla aparece inmediatamente en la lista de Inbound Rules con un ícono verde.

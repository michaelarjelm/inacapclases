01 — Usuarios
Bloque 01 · Criterio 3.1.3
Usuarios
y sesión

Los permisos no tienen sentido sin entender primero quién es quién en el sistema. Cada archivo pertenece a un usuario y a un grupo, así que empezamos por ahí.

Concepto
01 — Usuarios · Tipos
Tipos de usuario
en Linux

Linux es multiusuario: muchas cuentas pueden coexistir en el mismo sistema. Cada cuenta tiene un número identificador, el UID (User ID). Hay tres tipos:

root
Administrador
UID 0. Control total del sistema. No tiene restricciones de permisos.
1000+
Usuarios normales
Personas reales (ej. ec2-user). UID desde 1000. Permisos limitados.
1-999
Usuarios de servicio
Cuentas de sistema para servicios (apache, sshd). No inician sesión.
💡
Dónde viven los usuarios y grupos

Los usuarios se definen en el archivo /etc/passwd y los grupos en /etc/group. Cada línea de /etc/passwd tiene 7 campos separados por dos puntos: ana:x:1001:1001::/home/ana:/bin/bash es nombre : x : UID : GID : comentario : carpeta_home : shell. La x significa que la contraseña real está cifrada en otro archivo (/etc/shadow).

Pasos
01 — Usuarios · Identidad
¿Quién soy y a qué
grupos pertenezco?

Estos tres comandos no cambian nada: solo te informan quién eres. Los vas a usar todo el tiempo.

Terminal — sesion SSH en el servidor
$ whoami ec2-user # mi nombre de usuario $ id uid=1000(ec2-user) gid=1000(ec2-user) groups=1000(ec2-user),4(adm) $ groups ec2-user adm wheel # solo los nombres de mis grupos
💡
Cómo leer la salida de id

uid=1000(ec2-user) es tu identificador de usuario. gid=1000(ec2-user) es tu grupo principal (el que se asigna a los archivos que creas). groups=... lista todos los grupos a los que perteneces, incluidos los secundarios. Todo esto importa porque los permisos se deciden segun a qué grupo perteneces.

Pasos
01 — Usuarios · Crear cuentas
Crear un grupo
y un usuario

Crear cuentas es tarea de administrador, por eso cada comando lleva sudo. Ojo: cuando un comando funciona bien, Linux no imprime nada. El silencio es éxito.

Terminal — sesion SSH en el servidor
# 1. Crear un grupo (no imprime nada = ok) $ sudo groupadd desarrollo # 2. Crear el usuario ana. -m crea su carpeta /home/ana $ sudo useradd -m ana # 3. Ponerle contraseña (te la pide dos veces, no se ve al escribir) $ sudo passwd ana New password: Retype new password: passwd: all authentication tokens updated successfully. # 4. Agregar a ana al grupo desarrollo. -aG = Anadir al Grupo $ sudo usermod -aG desarrollo ana # 5. Comprobar que quedo en el grupo $ id ana uid=1001(ana) gid=1001(ana) groups=1001(ana),1002(desarrollo)
⚠
Nunca olvides la a en -aG

-aG AGREGA el grupo sin tocar los demás. Si escribes solo -G desarrollo (sin la a), REEMPLAZAS todos los grupos del usuario por ese uno solo y pierdes los demás. La a es de "append" (añadir).

⚠
Si olvidas sudo

Verás el error useradd: Permission denied. o groupadd: cannot lock /etc/group. Es porque un usuario normal no puede crear cuentas. Antepón sudo y reintenta.

02 — File System
Bloque 02 · Criterio 3.1.3
File System
y directorios

En Linux todo cuelga de una única raíz: la barra /. No hay letras de unidad como C: o D: de Windows. Conocer el árbol te permite saber dónde vive cada cosa.

Concepto
02 — File System · FHS
La estructura
de directorios

El estándar FHS (Filesystem Hierarchy Standard) define qué va en cada directorio. En Windows escribirías C:\Users\ana; en Linux el equivalente es /home/ana, y todo parte de /. Los directorios más importantes:

DirectorioQué contiene
/La raíz. Todo lo demás cuelga de aquí.
/rootCarpeta personal del usuario root.
/homeCarpetas personales de los usuarios normales (/home/ana).
/etcArchivos de configuración del sistema y servicios.
/varDatos variables: logs (/var/log), colas, sitios web.
/tmpArchivos temporales. Se borran al reiniciar.
/optSoftware y proyectos instalados aparte. Aquí haremos la práctica.
/bin, /usrProgramas y comandos del sistema.
Pasos
02 — File System · Navegación
Moverse y gestionar
archivos por CLI
Terminal — sesion SSH en el servidor
$ pwd # ¿donde estoy? /home/ec2-user $ ls -l # listar con detalle (permisos, dueño, tamano) $ cd /var/log # entrar a otra carpeta $ cd ~ # ~ es un atajo a mi carpeta personal # Crear, copiar, mover, borrar $ mkdir proyecto # crear un directorio $ touch proyecto/notas.txt # crear un archivo vacio $ cp notas.txt copia.txt # copiar (cp = copy) $ mv copia.txt /tmp/ # mover (mv = move) $ rm /tmp/copia.txt # borrar (rm = remove, no hay papelera)
✓
Leer la salida de ls -l columna por columna

Una línea como -rw-r--r-- 1 ec2-user ec2-user 1024 nov 3 notas.txt tiene, en orden: 1) tipo y permisos (-rw-r--r--), 2) número de enlaces (1), 3) usuario dueño (ec2-user), 4) grupo dueño (ec2-user), 5) tamaño en bytes (1024), 6) fecha y 7) nombre. Ese primer bloque de letras es justo lo que estudiamos en el resto de la clase.

03 — Propietarios
Bloque 03 · Criterio 3.1.3
Propietario
y grupo

Cada archivo pertenece a un usuario (propietario) y a un grupo. De esa pertenencia dependen los permisos. Antes de dar permisos, hay que saber a quién pertenece la cosa.

Concepto + Pasos
03 — Propietarios · chown / chgrp
Cambiar dueño
y grupo

Cada archivo tiene un usuario propietario y un grupo propietario. Se cambian con chown (change owner) y chgrp (change group). Cambiar de dueño es cosa de administrador, así que siempre con sudo.

Terminal — sesion SSH en el servidor
# Ver dueño y grupo actuales $ ls -l notas.txt -rw-r--r-- 1 ec2-user ec2-user 1024 notas.txt ^dueño ^grupo # Cambiar solo el dueño a ana $ sudo chown ana notas.txt $ ls -l notas.txt -rw-r--r-- 1 ana ec2-user 1024 notas.txt # Cambiar dueño Y grupo a la vez, con el formato dueño:grupo $ sudo chown ana:desarrollo notas.txt $ ls -l notas.txt -rw-r--r-- 1 ana desarrollo 1024 notas.txt # Aplicar recursivamente a un directorio y todo su contenido $ sudo chown -R ana:desarrollo proyecto/
💡
Qué significa ana:desarrollo y la -R

Los dos puntos separan dueño (izquierda) de grupo (derecha): ana:desarrollo = dueño ana, grupo desarrollo. Si escribes solo ana cambia únicamente el dueño. La opción -R es de "recursivo": aplica el cambio a la carpeta y a TODO lo que hay dentro, en un solo comando.

⚠
Si olvidas sudo

Aparece chown: changing ownership of 'notas.txt': Operation not permitted. Regalar un archivo a otro usuario solo lo puede hacer root. Antepón sudo.

04 — Permisos básicos
Bloque 04 · Criterio 3.1.3
Permisos
básicos

El corazón de la clase. Tres permisos (leer, escribir, ejecutar) aplicados a tres categorías (dueño, grupo, otros). Con eso controlas todo el acceso al sistema de archivos.

Concepto
04 — Permisos · Cómo se leen
Las tres ternas
de permisos

Los 10 caracteres al inicio de ls -l se dividen en el tipo (1 carácter) y tres ternas de 3 caracteres cada una:

-
Tipo
- archivo · d directorio
rwx
Usuario
el dueño
r-x
Grupo
el grupo dueño
r--
Otros
todos los demás

Cada terna tiene tres posiciones fijas: r (read/leer), w (write/escribir) y x (execute/ejecutar). Si el permiso está, aparece la letra; si no está, aparece un guion - en esa posición. El ejemplo de arriba, -rwxr-xr-x, se lee: es un archivo; el dueño puede leer, escribir y ejecutar; el grupo puede leer y ejecutar pero no escribir; y los otros igual que el grupo.

💡
En directorios las letras cambian de significado

En un directorio, r = poder listar su contenido con ls, w = poder crear o borrar archivos dentro, x = poder entrar al directorio con cd. Un directorio sin x no se puede abrir, aunque tenga r.

Concepto
04 — Permisos · Notación octal
Permisos en
números (octal)

En vez de escribir rwxr-xr-x, se puede usar un número por terna. Cada permiso vale una cantidad fija y se suman:

r=4 · w=2 · x=1
Cada letra vale un número
Un guion (-) vale 0. rwx = 4+2+1 = 7 · rw- = 4+2 = 6 · r-x = 4+1 = 5 · r-- = 4 · --- = 0
7 5 5
Un dígito por terna
Primero usuario, luego grupo, luego otros. 755 = rwx r-x r-x
✓
Ejemplo resuelto: ¿cuánto es 640?

Terna del dueño: rw- = 4+2+0 = 6. Terna del grupo: r-- = 4+0+0 = 4. Terna de otros: --- = 0+0+0 = 0. Resultado: 640 = rw- r-- --- = el dueño lee y escribe, el grupo solo lee, los demás no pueden hacer nada.

OctalSimbólicoUso típico
644rw- r-- r--Archivos normales (dueño edita, resto lee)
755rwx r-x r-xDirectorios y programas ejecutables
640rw- r-- ---Archivo del equipo (dueño edita, grupo lee)
600rw- --- ---Archivos privados (solo el dueño)
700rwx --- ---Carpetas privadas
Pasos
04 — Permisos · chmod
Cambiar permisos
con chmod

chmod (change mode) acepta dos maneras de escribir lo mismo. A propósito veremos las dos para que reconozcas ambas en un examen o en internet.

Terminal — sesion SSH en el servidor
# --- Forma SIMBOLICA: a quien + que permiso --- # quien: u=usuario g=grupo o=otros a=todos # accion: +anade -quita =deja exactamente eso $ chmod u+x script.sh # dar ejecucion al dueño $ chmod g-w notas.txt # quitar escritura al grupo $ chmod o=r notas.txt # otros: exactamente solo lectura # --- Forma OCTAL: los tres digitos de una vez --- $ chmod 644 notas.txt # rw- r-- r-- $ chmod 755 script.sh # rwx r-x r-x $ chmod 640 notas.txt # rw- r-- --- # Comprobar SIEMPRE con ls -l despues de cambiar $ ls -l script.sh -rwxr-xr-x 1 ec2-user ec2-user 220 script.sh
💡
¿Cuándo cada forma?

La octal (644) fija los tres grupos de golpe: úsala cuando quieres dejar el archivo en un estado exacto. La simbólica (u+x) toca solo lo que nombras y deja el resto igual: úsala cuando solo quieres sumar o quitar un permiso puntual sin recalcular todo.

⚠
Si no eres el dueño

Verás chmod: changing permissions of 'notas.txt': Operation not permitted. Solo el dueño del archivo (o root con sudo) puede cambiar sus permisos.

05 — umask
Bloque 05 · Criterio 3.1.3
umask

Cuando creas un archivo nuevo, ¿de dónde salen sus permisos por defecto? De umask. Es una máscara que RESTA permisos a lo que se crea.

Concepto + Pasos
06 — umask · Cómo funciona
Permisos por
defecto con umask

El sistema parte de una base fija: 666 para archivos y 777 para directorios (los archivos nunca nacen con permiso de ejecución). La umask se resta de esa base para obtener el permiso final.

Baseumask 022Resultado
Archivo666- 022644 (rw-r--r--)
Directorio777- 022755 (rwxr-xr-x)
Terminal — sesion SSH en el servidor
$ umask # ver la mascara actual 0022 # el primer 0 es para permisos especiales # Probar: crear archivo y directorio y ver que permisos les tocan $ touch a.txt $ mkdir dir1 $ ls -l -rw-r--r-- 1 ec2-user ec2-user 0 a.txt # 644 drwxr-xr-x 2 ec2-user ec2-user 4096 dir1 # 755 # Cambiar la mascara a 077 (mas restrictivo = mas privado) $ umask 077 $ touch b.txt && ls -l b.txt -rw------- 1 ec2-user ec2-user 0 b.txt # 600: solo el dueño
✓
Truco para no confundirte

umask no "da" permisos, los "quita". Cada dígito de la máscara dice cuánto restar a esa terna. Con 022: al grupo le resta 2 (le quita la w) y a otros igual, por eso los archivos quedan en 644. El cambio con umask dura solo mientras no cierres la sesión.

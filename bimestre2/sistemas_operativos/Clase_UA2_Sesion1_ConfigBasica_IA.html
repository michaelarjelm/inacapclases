01 — Antigravity CLI
Bloque 01
¿Qué es
Antigravity CLI?

La herramienta de terminal de Google que reemplaza a Gemini CLI. Te permite dar instrucciones a agentes de IA directamente desde la línea de comandos.

Concepto
01 — Antigravity CLI · Qué es
El sucesor de
Gemini CLI

Antigravity CLI (comando: agy) es la interfaz de línea de comandos de Google para interactuar con agentes de IA. Reemplaza a Gemini CLI, que dejó de funcionar el 18 de junio de 2026.

Está construido en Go, es más rápido y soporta múltiples agentes trabajando en paralelo. Lo que mantiene de Gemini CLI: Skills, Hooks, Subagentes y Plugins.

Gemini CLI (descontinuado)

gemini --model gemini-pro
"haz esto en el servidor"

Un agente, una tarea, síncrono.

Antigravity CLI (actual)

agy
"haz esto en el servidor"

Múltiples agentes, tareas paralelas, asíncrono.

🤖
¿Por qué lo usamos en sysadmin?

Porque convierte tareas repetitivas (actualizar, configurar firewall, preparar AD DS) en instrucciones en lenguaje natural. El agente sabe qué comandos ejecutar — tú solo describes el resultado que quieres.

Concepto
01 — Antigravity CLI · Modo de trabajo
¿Cómo trabaja
el agente?

El agente de Antigravity CLI opera en dos modos. En esta sesión trabajaremos en modo reactivo:

  • Modo reactivo: tú escribes una instrucción, el agente la ejecuta y reporta el resultado. Tú tienes el control total en todo momento.
  • Modo autónomo: defines un objetivo o un evento y el agente actúa solo cuando se cumple la condición. Lo veremos en sesiones futuras.
💡
La diferencia clave

En modo reactivo tú eres el director y el agente es quien ejecuta. En modo autónomo el agente toma decisiones dentro de los límites que tú le definiste. Hoy empezamos como directores.

02 — Fundamentos
Bloque 02
Prompts,
tokens y modelos

Antes de usar el agente, es importante entender cómo funciona por dentro. Tres conceptos que explican el 80% de su comportamiento.

Concepto
02 — Fundamentos · Prompt
¿Qué es
un prompt?

Un prompt es la instrucción que le das al agente. Es texto en lenguaje natural — no necesitas saber programar para escribirlo. El modelo lo interpreta y decide qué acciones tomar.

Hay dos tipos de prompt que usaremos:

  • Prompt de sistema (context): define quién es el agente, qué puede hacer y cuáles son sus restricciones. Se escribe una vez al construir el agente.
  • Prompt de usuario: la instrucción que le das en cada conversación. "Actualiza el servidor", "Crea una regla de firewall para el puerto 443".
🤖
El prompt de sistema es el más importante

Es la diferencia entre un agente genérico que puede hacer cualquier cosa y un administrador de servidores especializado que sabe exactamente qué servidor gestiona, qué puede hacer y qué no.

Concepto
02 — Fundamentos · Tokens y modelos
Tokens
y modelos

Un token es la unidad de texto que procesa el modelo. Aproximadamente 1 token = 4 caracteres en inglés, algo menos en español. Todo lo que escribes — y todo lo que responde el agente — consume tokens.

Un modelo es el motor de IA detrás del agente. Antigravity CLI usa los modelos de Google. Los más relevantes para sysadmin:

  • Gemini 2.5 Pro: el más capaz. Ideal para tareas complejas, análisis de logs, planificación de AD DS.
  • Gemini 2.5 Flash: más rápido y liviano. Suficiente para tareas operativas como actualizar o configurar firewall.
⚠
Contexto limitado por tokens

Cada modelo tiene un límite de tokens por conversación (context window). Si la conversación se vuelve muy larga, el agente puede "olvidar" instrucciones anteriores. Por eso el prompt de sistema debe ser conciso y preciso.

03 — Buenas prácticas
Bloque 03
Cómo pedir
bien

La calidad de la respuesta del agente depende directamente de la calidad de la instrucción. Estas prácticas marcan la diferencia entre un agente útil y uno que hace lo incorrecto.

Buenas prácticas
03 — Buenas prácticas · Cómo escribir prompts efectivos
Las 4 reglas
del buen prompt
1
Sé específico — describe el resultado, no el proceso
❌ "Haz cosas de seguridad en el servidor"
✅ "Crea una regla de firewall de entrada que permita TCP en el puerto 443, nómbrala HTTPS-443"
2
Incluye el contexto necesario
❌ "Actualiza"
✅ "Verifica si hay actualizaciones pendientes en Windows Update, instálalas todas y avísame si necesita reiniciar antes de hacerlo"
3
Define el formato de respuesta
✅ "Al terminar, muéstrame: qué hiciste, resultado obtenido y próximo paso recomendado"
4
Establece restricciones explícitas cuando importan
✅ "No reinicies sin pedirme confirmación primero"
✅ "No elimines reglas de firewall existentes"

Sin RDP. Un solo comando desde tu terminal — Windows o Linux — y tienes una sesión PowerShell completa dentro del servidor.

Paso previo
04 — SSH · Habilitar en Windows Server
Habilitar SSH
en el servidor

Este paso se hace una sola vez, desde RDP. Abre PowerShell como administrador dentro del servidor y ejecuta:

PowerShell — dentro del servidor (RDP)Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
PowerShell — iniciar el servicio y dejarlo automáticoStart-Service sshd Set-Service -Name sshd -StartupType Automatic

Luego, desde la consola de AWS, abre el puerto 22 en el Security Group de la instancia:

1
EC2 → Instancia → Security → Security Groups
Haz clic en el Security Group vinculado a tu instancia.
2
Inbound Rules → Edit inbound rules → Add rule
Tipo: SSH — Puerto: 22 — Source: My IP (o 0.0.0.0/0 para cualquier origen).
3
Save rules
El puerto 22 queda abierto y el servidor acepta conexiones SSH desde ese momento.
💡
Esta es la última vez que usas RDP

Una vez habilitado SSH, todas las sesiones siguientes son desde tu terminal. No necesitas volver a abrir RDP.

Conexión
04 — SSH · Permisos y conexión
Preparar la clave
y conectar

Antes de conectar, el archivo .pem necesita permisos restringidos — SSH rechaza claves con permisos abiertos.

Windows — PowerShell

icacls "SRV-001.pem" /inheritance:r
/grant:r "%USERNAME%:R"

Linux / macOS — Terminal

chmod 400 SRV-001.pem

Luego conecta — el comando es el mismo en ambos sistemas:

PowerShell / Terminalssh -i SRV-001.pem Administrator@<IP-del-servidor>
Sesión SSH exitosa — ejemploPS C:\Users\Mike> ssh -i SRV-001.pem Administrator@100.31.109.52 Administrator@100.31.109.52's password: ············ Windows PowerShell Copyright (C) Microsoft Corporation. All rights reserved. PS C:\Users\Administrator> _
💡
La contraseña no se ve mientras la escribes

SSH no muestra asteriscos ni caracteres al tipear. Escribe la contraseña de Administrator y presiona Enter — aunque la pantalla esté en blanco, sí la está recibiendo.

Desde la sesión SSH, ejecuta el instalador oficial de Google:

El instalador actualiza el PATH del sistema pero no el de la sesión actual. Recárgalo sin cerrar la conexión:

PowerShell — recargar PATH en la sesión$env:PATH = [System.Environment]::GetEnvironmentVariable("PATH","Machine")+";"+[System.Environment]::GetEnvironmentVariable("PATH","User")

Luego inicia la autenticación con Google:

Autenticación OAuth — lo que verás en pantallaPS C:\Users\Administrator> agy auth login Visita este enlace en tu navegador para autenticarte: https://accounts.google.com/o/oauth2/auth?client_id=agy... Ingresa el código de autorización: > ██████████████████████ Autenticación completada. Prompts
06 — Configuración · Hostname, idioma e IP
Hostname,
idioma e IP
Prompt — HostnameCambia el nombre de este servidor a JPS-WinSRV. Avísame cuando esté listo para reiniciar y espera mi confirmación antes de hacerlo.
Prompt — IdiomaInstala el paquete de idioma Español (Chile) y configúralo como idioma de pantalla del sistema. Avísame cuando necesite cerrar sesión para aplicar el cambio.
Prompt — IP estáticaVoy a configurar la IP de este servidor de forma estática. Antes de ejecutar nada, pídeme uno por uno los siguientes datos: IP address, Máscara de subred, Gateway predeterminado, DNS preferido y DNS alternativo. Espera mi respuesta a cada uno antes de continuar. Cuando tengas todos, muéstramelos y pide mi confirmación final. Recién ahí aplica el cambio.
⚡
La sesión SSH caerá — es normal y esperado

Al cambiar el adaptador de DHCP a estático, Windows interrumpe la conexión TCP activa. El servidor no se daña: la IP privada es la misma que tenía antes.

Qué hacer: espera 15-20 segundos y reconecta con el mismo comando de siempre:
ssh -i SRV-001.pem Administrator@<IP-publica-EC2>

Si no reconecta después de 30 segundos, detén e inicia la instancia desde la consola de AWS (Stop → Start).

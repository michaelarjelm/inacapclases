Dominamos el CRUD, los subdocumentos y los arreglos: sabemos encontrar documentos. Pero find no sabe sumar, promediar ni agrupar. Hoy damos el salto de consultar a analizar.

Bloque 01

Del find al
aggregate

El framework de agregación procesa los documentos en etapas encadenadas. Cada etapa recibe documentos, los transforma y se los pasa a la siguiente.

Concepto

Aggregation — La idea

Una tubería
de etapas

aggregate() recibe un arreglo de etapas. Los documentos entran por la primera, fluyen de una a otra y salen transformados por la última. Es una línea de ensamblaje: cada etapa hace un trabajo y pasa el resultado a la siguiente.

partidos → $match → $group → $sort → resultado
🔗
El orden importa

Las etapas se ejecutan de izquierda a derecha. Filtrar primero con $match y agrupar después no es lo mismo que al revés: cambia el resultado y el rendimiento.

Concepto

Aggregation — Cómo fluye la data

La salida de una
es la entrada de la otra

La clave: cada etapa no ve la colección original. Solo recibe los documentos que le pasó la etapa anterior, los transforma, y le entrega su resultado a la siguiente. Sigamos un pipeline real y veamos cómo cambia el flujo paso a paso:

El pipeline que vamos a trazar 
db.partidos.aggregate([
  { $group: { "_id": "$fase", "cantidad": { $sum: 1 } } },
  { $sort: { "cantidad": -1 } },
  { $limit: 3 }
])
Etapa
Qué le hace al flujo
Documentos que salen
partidos
La colección completa entra al pipeline.
900todos los partidos
$group
Colapsa los 900 partidos en un documento por fase.
5uno por fase
$sort
Reordena esos 5 de mayor a menor. No agrega ni quita.
5mismos, reordenados
$limit
Recorta y deja solo los 3 primeros del flujo ordenado.
3resultado final
🧠
La idea que hay que grabarse

$sort nunca vio los 900 partidos: solo ordenó los 5 que le entregó $group. Por eso el orden de las etapas lo es todo: cada una trabaja sobre lo que recibe, no sobre la colección.

Concepto

Aggregation — Sintaxis básica

Cómo se
escribe

Antes de las etapas, leamos el esqueleto. Es la primera vez que ves esta estructura, así que vamos pieza por pieza:

Anatomía de un pipeline 
db.partidos.aggregate([          // metodo + corchete: abre el ARREGLO de etapas
  { $match: { "mundial": 2014 } },   // etapa 1 (un objeto), la coma la separa
  { $group: { "_id": "$fase" } }     // etapa 2 (otro objeto), la ultima sin coma
])                              // cierra el arreglo
[ ]
Los corchetes: el pipeline es un arreglo, una lista ordenada de etapas.
{ }
Las llaves: cada etapa es un objeto independiente.
,
La coma separa una etapa de la siguiente. La última no lleva coma.
$match
La clave de cada etapa empieza con $ y nombra el operador.
"$fase"
Dentro de una etapa, "$campo" es el valor de un campo del documento.
aggregate()
Se llama sobre la colección, igual que find().
💡
El cambio frente a find

find() recibe un objeto { }. aggregate() recibe un arreglo [ ] de objetos, porque son varias etapas en orden.

Concepto

Aggregation — Etapas principales

Las etapas
de hoy

Con estas seis etapas se resuelve la enorme mayoría de los análisis:

$match
filtra documentos (como find)
{ $match: { fase: "Final" } }
$project
elige y transforma campos
{ $project: { mundial: 1 } }
$group
agrupa y resume
{ $group: { _id: "$fase" } }
$sort
ordena los resultados
{ $sort: { goles: -1 } }
$limit
recorta a los primeros N
{ $limit: 10 }
$unwind
desarma un arreglo
{ $unwind: "$goleadores" }
Comando

Aggregation — Primer pipeline

aggregate + $count

MongoDB Shell 
// El pipeline es un ARREGLO de etapas, en orden
db.partidos.aggregate([
  { $match: { "fase": "Final" } },   // 1) dejar solo finales
  { $count: "total_finales" }        // 2) contarlas
])
// -> [ { total_finales: 21 } ]   (1950 no tuvo final: grupo final)
Qué hace cada parte
{ $match: { ... } }
Etapa 1: deja pasar solo los partidos cuya fase es "Final". El resto no continúa.
{ $count: "total_finales" }
Etapa 2: cuenta los que llegaron y guarda el número en un campo llamado total_finales (el nombre lo eliges tú).

Compara con find: find({ fase: "Final" }) te devuelve los documentos. El pipeline, en cambio, los procesa etapa por etapa: filtra y luego cuenta.

Bloque 02

$match y
$project

Las dos etapas más fáciles de entender: una filtra (lo que ya sabes de find), la otra elige y crea campos.

Concepto

$match — El filtro del pipeline

$match es el
find de aggregate

$match usa exactamente la misma sintaxis que el filtro de find(): mismos operadores ($gt, $in, $or...), misma dot notation.

Regla de oro: pon $match lo antes posible. Si reduces los documentos al inicio, todas las etapas siguientes trabajan sobre menos datos.

💡
Ya lo sabes

Todo lo aprendido en S2 sobre filtros sirve igual dentro de $match. No es sintaxis nueva.

Comando

$match — Filtrar en el pipeline

aggregate con $match

MongoDB Shell 
// Partidos del Mundial 2014
db.partidos.aggregate([
  { $match: { "mundial": 2014 } }
])

// Finales que se fueron a tiempo extra (mismos operadores que find)
db.partidos.aggregate([
  { $match: { "fase": "Final", "tiempo_extra": true } }
])

// Dot notation tambien funciona: partidos jugados en Brasil
db.partidos.aggregate([
  { $match: { "sede.pais": "Brasil" } }
])
Qué hace cada parte
$match
La etapa que filtra. Recibe el mismo objeto de condiciones que ya usas en find().
{ "mundial": 2014 }
La condición: deja pasar solo los documentos donde el campo vale exactamente eso.
"sede.pais": "Brasil"
La dot notation de S3 también funciona aquí: filtra por un campo dentro de un subdocumento.

Si solo necesitas filtrar, find es más corto. El pipeline gana cuando ese filtro es el primer paso de un análisis mayor.

Concepto

$project — Elegir y crear campos

$project
transforma

$project es la proyección de S2 con superpoderes: además de incluir (1) o excluir (0) campos, puede crear campos nuevos calculados a partir de otros.

Para calcular usamos operadores de expresión como $add (sumar), $subtract (restar), $multiply y $concat (unir textos). Los campos existentes se referencian con comillas y signo peso: "$local.goles".

💲
El signo peso ($)

"$campo" significa "el valor de ese campo". Sin el $ sería el texto literal. { x: "$local.goles" } copia el valor; { x: "local.goles" } guarda la cadena.

Comando

$project — Campos calculados

aggregate con $project

MongoDB Shell 
// Finales: mostrar selecciones y el total de goles del partido
db.partidos.aggregate([
  { $match: { "fase": "Final" } },
  { $project: {
      "_id": 0,
      "mundial": 1,
      "local": "$local.seleccion",
      "visitante": "$visitante.seleccion",
      "total_goles": { $add: [ "$local.goles", "$visitante.goles" ] }
  } }
])
Qué hace cada parte
"_id": 0
Oculta el _id en la salida (por defecto siempre aparece).
"mundial": 1
Incluye el campo tal cual viene en el documento.
"local": "$local.seleccion"
Crea un campo local con el valor de local.seleccion. El $ es lo que trae el valor; sin él sería el texto literal.
"total_goles": { $add: [...] }
Crea un campo nuevo, calculado: suma los goles de local y visitante.

total_goles no existe en la colección: lo creamos al vuelo. El pipeline no modifica los documentos guardados, solo produce una vista nueva.

Resultado

$project — Salida

Finales con total_goles

Campo calculado al vuelo
[
  { mundial: 2010, local: "Paises Bajos", visitante: "Espana", total_goles: 1 },
  { mundial: 2014, local: "Alemania",     visitante: "Argentina", total_goles: 1 },
  { mundial: 2018, local: "Francia",      visitante: "Croacia",   total_goles: 6 },
  { mundial: 2022, local: "Argentina",   visitante: "Francia",   total_goles: 6 }
  // ... una fila por cada final
]

Bloque 03

$group

La etapa estrella de la agregación: junta documentos por un criterio y calcula totales, promedios y máximos sobre cada grupo.

Concepto

$group — Cómo funciona

Agrupar
y resumir

$group tiene siempre un campo _id: es el criterio de agrupación. Todos los documentos con el mismo _id forman un grupo, y por cada grupo sale un solo documento de resultado.

Junto al _id definimos campos calculados con acumuladores: operadores que recorren todo el grupo y devuelven un número. El truco más usado: { $sum: 1 } cuenta cuántos documentos cayeron en el grupo.

⚠
El _id es obligatorio

Para agrupar TODA la colección en un único resultado se usa _id: null. Olvidar el _id es el error más común al empezar con $group.

Concepto

$group — Acumuladores

Los acumuladores

Operadores que resumen los valores de cada grupo:

$sum
suma valores (o cuenta con 1)
cantidad: { $sum: 1 }
$avg
promedio del grupo
prom: { $avg: "$local.goles" }
$max
valor máximo
tope: { $max: "$local.goles" }
$min
valor mínimo
piso: { $min: "$local.goles" }
$first
primer valor del grupo
sel: { $first: "$local.seleccion" }
$push
junta valores en un arreglo
lista: { $push: "$mundial" }
Comando

$group — Contar y sumar

aggregate con $group

MongoDB Shell 
// Cuantos partidos hay por fase
db.partidos.aggregate([
  { $group: { "_id": "$fase", "cantidad": { $sum: 1 } } }
])

// Goles de local y de visita, sumados por mundial
db.partidos.aggregate([
  { $group: {
      "_id": "$mundial",
      "goles_local": { $sum: "$local.goles" },
      "goles_visita": { $sum: "$visitante.goles" }
  } },
  { $sort: { "_id": 1 } }   // ordenar por anio
])
Qué hace cada parte
$group
La etapa que agrupa y resume.
"_id": "$fase"
El criterio de agrupación: junta en un mismo grupo todos los partidos que comparten la misma fase. Es el corazón de la etapa; el $ trae el valor del campo.
"cantidad":
El nombre del campo de salida. Lo inventas tú; aparecerá así en el resultado.
{ $sum: 1 }
El acumulador: suma un 1 por cada documento del grupo, es decir, los cuenta. { $sum: "$local.goles" } en cambio suma valores reales.

Cambia solo el _id y agrupas por otra cosa (selección, país, año). Cambia el acumulador y en vez de contar, promedias o sumas. Esos dos componentes definen todo el análisis.

Resultado

$group — Partidos por fase

Un documento por grupo

db.partidos.aggregate([ { $group: ... } ])
[
  { _id: "Grupos",    cantidad: 624 },
  { _id: "Octavos",   cantidad: 56 },
  { _id: "Cuartos",   cantidad: 88 },
  { _id: "Semifinal", cantidad: 44 },
  { _id: "Final",     cantidad: 21 }
]

Cada fase distinta produjo exactamente un documento. El orden de salida de $group no está garantizado: por eso casi siempre lo seguimos de un $sort.

Bloque 04

$sort, $limit
y $skip

Las etapas que convierten un resumen en un ranking: ordenar de mayor a menor y quedarse con el top N.

Concepto

$sort / $limit / $skip — Rankings

Ordenar y
recortar

  • $sort: ordena. 1 ascendente, -1 descendente.
  • $limit: deja solo los primeros N documentos.
  • $skip: salta los primeros N (útil para paginar).

El patrón clásico de "top 5" es $group → $sort (desc) → $limit: 5. Primero resumes, luego ordenas por el campo calculado, y al final recortas.

⚠
$sort siempre antes de $limit

Si limitas antes de ordenar, te quedas con N documentos cualesquiera y luego los ordenas: NO es el top real. El orden de las etapas cambia el resultado.

Comando

$sort + $limit — Top N

aggregate top 5 mundiales

MongoDB Shell 
// Los 5 mundiales con mas goles de local
db.partidos.aggregate([
  { $group: { "_id": "$mundial", "goles": { $sum: "$local.goles" } } },
  { $sort: { "goles": -1 } },   // de mayor a menor
  { $limit: 5 }                  // solo los 5 primeros
])

// Promedio de goles de local por mundial, del mas goleador al menos
db.partidos.aggregate([
  { $group: { "_id": "$mundial", "promedio": { $avg: "$local.goles" } } },
  { $sort: { "promedio": -1 } }
])
Qué hace cada parte
{ $sort: { "goles": -1 } }
Ordena por el campo goles. El -1 es descendente (de mayor a menor); 1 sería ascendente.
{ $limit: 5 }
Deja solo los 5 primeros del flujo ya ordenado. Por eso va después de $sort.

Fíjate que $sort ordena por goles, el campo que creó $group. Una vez calculado, se usa igual que cualquier otro campo en las etapas siguientes.

Bloque 05

$unwind

Para analizar lo que vive dentro de un arreglo (goleadores, tarjetas) primero hay que desarmarlo. Aquí entra en juego lo que modelamos en S3.

Concepto

$unwind — Desarmar arreglos

Una fila por
elemento

$unwind toma un campo de tipo arreglo y genera una copia del documento por cada elemento. Un partido con 3 goleadores se convierte en 3 documentos, cada uno con un solo goleador (ya no un arreglo, sino el objeto suelto).

Antes (1 documento)
goleadores: [ A, B, C ]

Un partido con un arreglo de 3 goleadores adentro.

Después de $unwind (3 documentos)
goleadores: A / B / C

Tres copias del partido, cada una con un goleador suelto. Listo para $group.

🔑
La dupla mágica

$unwind + $group es el patrón para analizar arreglos de subdocumentos: desarmas y luego agrupas por jugador, selección, tipo de tarjeta, etc.

Comando

$unwind — Desarmar goleadores

aggregate con $unwind

MongoDB Shell 
// Desarmar el arreglo goleadores de la final del 2010
db.partidos.aggregate([
  { $match: { "mundial": 2010, "fase": "Final" } },
  { $unwind: "$goleadores" },
  { $project: {
      "_id": 0,
      "jugador": "$goleadores.jugador",
      "minuto": "$goleadores.minuto"
  } }
])
// -> [ { jugador: "Andres Iniesta", minuto: 116 } ]
Qué hace cada parte
$unwind: "$goleadores"
Desarma el arreglo goleadores: genera una copia del documento por cada elemento del arreglo.
"$goleadores.jugador"
Tras desarmar, goleadores ya no es un arreglo sino un objeto suelto: accedes a sus campos con punto, sin pensar en posiciones.

Sin $unwind no se puede agrupar por jugador: estarían todos atrapados dentro del arreglo. Desarmar es el paso previo obligado para analizar lo que vive en una lista.

Bloque 06

Pipeline
completo

Juntamos todo para responder la pregunta con más gancho del módulo: ¿quién es el máximo goleador de la historia de los Mundiales?

Comando

Pipeline completo — Top goleadores

$unwind + $group + $sort + $limit

MongoDB Shell 
// Maximos goleadores de la historia de los Mundiales
db.partidos.aggregate([
  { $unwind: "$goleadores" },                      // 1) un doc por gol
  { $match: { "goleadores.autogol": false } },     // 2) excluir autogoles
  { $group: {                                       // 3) agrupar por jugador
      "_id": "$goleadores.jugador",
      "goles": { $sum: 1 },
      "seleccion": { $first: "$goleadores.seleccion" }
  } },
  { $sort: { "goles": -1 } },                    // 4) del que mas marco
  { $limit: 10 }                                  // 5) top 10
])
Etapa por etapa
$unwind: "$goleadores"
Desarma: un documento por cada gol marcado en la historia.
$match: { autogol: false }
Descarta los autogoles: no cuentan para el goleador.
"_id": "$goleadores.jugador"
Agrupa por nombre de jugador: todos sus goles caen en el mismo grupo.
"goles": { $sum: 1 }
Cuenta cuántos goles quedaron en cada grupo.
"seleccion": { $first: ... }
Toma la selección del primer gol del grupo, solo para mostrarla.
$sort + $limit
Ordena de mayor a menor y deja el top 10.

Lee el pipeline de arriba hacia abajo como una frase: "desarma los goles, quita autogoles, cuenta por jugador, ordena y quédate con los 10 mejores".

Resultado

Pipeline completo — Top goleadores

Los máximos goleadores

Top 10 historico

Solución

Actividad — Soluciones E1 a E5

Solucionario parte 1

MongoDB Shell 
// E1 - Partidos por mundial
db.partidos.aggregate([
  { $group: { "_id": "$mundial", "partidos": { $sum: 1 } } },
  { $sort: { "_id": 1 } }
])

// E2 - Total de goles (local + visita) por mundial
db.partidos.aggregate([
  { $group: {
      "_id": "$mundial",
      "goles": { $sum: { $add: [ "$local.goles", "$visitante.goles" ] } }
  } },
  { $sort: { "_id": 1 } }
])

// E3 - Promedio de goles del local por fase
db.partidos.aggregate([
  { $group: { "_id": "$fase", "promedio_local": { $avg: "$local.goles" } } }
])

// E4 - Los 5 mundiales con mas partidos definidos por penales
db.partidos.aggregate([
  { $match: { "penales": true } },
  { $group: { "_id": "$mundial", "cantidad": { $sum: 1 } } },
  { $sort: { "cantidad": -1 } },
  { $limit: 5 }
])

// E5 - Cantidad de goles por seleccion
db.partidos.aggregate([
  { $unwind: "$goleadores" },
  { $group: { "_id": "$goleadores.seleccion", "goles": { $sum: 1 } } },
  { $sort: { "goles": -1 } }
])

En E2 el truco es anidar $add dentro de $sum: primero se suman los dos goles de cada partido, y ese total se va acumulando por mundial.

Solución

Actividad — Soluciones E6 a E10

Solucionario parte 2

MongoDB Shell 
// E6 - Maximo goleador de Argentina
db.partidos.aggregate([
  { $unwind: "$goleadores" },
  { $match: { "goleadores.seleccion": "Argentina" } },
  { $group: { "_id": "$goleadores.jugador", "goles": { $sum: 1 } } },
  { $sort: { "goles": -1 } },
  { $limit: 1 }
])

// E7 - Cantidad de tarjetas rojas por mundial
db.partidos.aggregate([
  { $unwind: "$tarjetas" },
  { $match: { "tarjetas.tipo": "roja" } },
  { $group: { "_id": "$mundial", "rojas": { $sum: 1 } } },
  { $sort: { "_id": 1 } }
])

// E8 - Total de goles de penal por mundial
db.partidos.aggregate([
  { $unwind: "$goleadores" },
  { $match: { "goleadores.de_penal": true } },
  { $group: { "_id": "$mundial", "goles_penal": { $sum: 1 } } },
  { $sort: { "_id": 1 } }
])

// E9 - Partido con mayor total de goles
db.partidos.aggregate([
  { $project: {
      "_id": 0, "mundial": 1, "fase": 1,
      "local": "$local.seleccion", "visitante": "$visitante.seleccion",
      "total_goles": { $add: [ "$local.goles", "$visitante.goles" ] }
  } },
  { $sort: { "total_goles": -1 } },
  { $limit: 1 }
])

// E10 - (Desafio) Top 10 goleadores historico, sin autogoles
db.partidos.aggregate([
  { $unwind: "$goleadores" },
  { $match: { "goleadores.autogol": false } },
  { $group: {
      "_id": "$goleadores.jugador",
      "goles": { $sum: 1 },
      "seleccion": { $first: "$goleadores.seleccion" }
  } },
  { $sort: { "goles": -1 } },
  { $limit: 10 }
])

E6, E7 y E8 comparten el patrón $unwind → $match → $group: desarmar el arreglo, filtrar el elemento que interesa y contarlo agrupado.

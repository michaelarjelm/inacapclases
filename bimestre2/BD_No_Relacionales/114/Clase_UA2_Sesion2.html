Bloque 01

Read
con filtros

Hasta ahora usábamos find({}) que devuelve todo. Ahora le pasamos condiciones para obtener exactamente lo que necesitamos.

Concepto

Read — Filtro básico

Match exacto

El argumento de find() es un objeto de consulta. Cuando especificamos { campo: valor }, MongoDB solo devuelve los documentos donde ese campo sea exactamente igual a ese valor.

La regla es simple: todo lo que ponemos dentro del objeto de consulta es una condición que debe cumplirse. Si ponemos varios campos, se cumplen todos al mismo tiempo (equivale a un AND).

🔍
Diferencia clave

find({}) → todos los documentos.   find({ campo: valor }) → solo los que coincidan.

Comando

Read — Filtro básico

find con match exacto

MongoDB Shell 
// Buscar todos los clientes del país "Peru"
db.clientes.find({ "country": "Peru" })

// Buscar clientes del departamento "Accounting"
db.clientes.find({ "department": "Accounting" })

// Dos condiciones al mismo tiempo (AND implícito)
db.clientes.find({
  "country": "Peru",
  "department": "Accounting"
})

Cada par campo: valor dentro del objeto actúa como una condición. Con múltiples pares, se devuelven solo los documentos que cumplen todas las condiciones.

Concepto

Read — Proyección

Seleccionar
campos

find() acepta un segundo argumento: la proyección. Sirve para indicar cuáles campos queremos ver en el resultado, en lugar de recibir el documento completo.

  • 1 incluye el campo en el resultado.
  • 0 excluye el campo del resultado.
  • Por defecto, _id siempre aparece — hay que excluirlo explícitamente con _id: 0.
💡
Para qué sirve

Cuando una colección tiene documentos muy grandes, la proyección reduce la cantidad de datos transferidos y hace más legible el resultado en pantalla.

Comando

Read — Proyección

find con proyección

MongoDB Shell 
// Solo mostrar first_name, last_name y salary (sin _id)
db.clientes.find(
  {},                                        // sin filtro = todos
  { "first_name": 1, "last_name": 1, "salary": 1, "_id": 0 }
)

// Filtro + proyección combinados
db.clientes.find(
  { "department": "Accounting" },
  { "first_name": 1, "last_name": 1, "salary": 1, "_id": 0 }
)

El primer argumento es la condición de búsqueda; el segundo es la proyección. Ambos son opcionales, pero siempre van en ese orden.

Concepto

Read — Operadores

Operadores de
comparación

Para comparar rangos de valores (mayor, menor, distinto) usamos operadores de consulta. Todos empiezan con $.

$gt
mayor que (>)
salary: { $gt: 3000000 }
$gte
mayor o igual (≥)
salary: { $gte: 3000000 }
$lt
menor que (<)
salary: { $lt: 2000000 }
$lte
menor o igual (≤)
salary: { $lte: 2000000 }
$ne
distinto de (≠)
department: { $ne: "Accounting" }
$in
está en la lista
department: { $in: ["Sales","Marketing"] }
$nin
no está en la lista
department: { $nin: ["Sales","Marketing"] }
Comando

Read — Operadores de comparación

find con operadores

MongoDB Shell 
// Clientes con salary mayor a 3.000.000
db.clientes.find({ "salary": { $gt: 3000000 } })

// Clientes con salary entre 2.000.000 y 4.000.000 (rango)
db.clientes.find({
  "salary": { $gte: 2000000, $lte: 4000000 }
})

// Clientes que NO sean del departamento Accounting
db.clientes.find({ "department": { $ne: "Accounting" } })

// Clientes de los departamentos Sales o Marketing
db.clientes.find({
  "department": { $in: [ "Sales", "Marketing" ] }
})

// Clientes que NO sean de Sales ni de Marketing ($nin = not in)
db.clientes.find({
  "department": { $nin: [ "Sales", "Marketing" ] }
})

El operador va dentro de un objeto { $op: valor } como valor del campo. $nin es el inverso exacto de $in: devuelve los documentos donde el campo no coincide con ninguno de los valores de la lista.

Concepto

Read — Operadores lógicos

Operadores
lógicos

Los operadores lógicos combinan o invierten condiciones. Todos reciben un arreglo de condiciones, excepto $not que opera sobre un solo campo.

$and
todas deben cumplirse
$and: [ {A}, {B} ]
$or
al menos una se cumple
$or: [ {A}, {B} ]
$not
niega una condición
campo: { $not: { $gt: 3000000 } }
$nor
ninguna se cumple
$nor: [ {A}, {B} ]
Comando

Read — Operadores lógicos

find con $or

MongoDB Shell 
// Clientes de género "Female" O con salary mayor a 4.000.000
db.clientes.find({
  $or: [
    { "gender": "Female" },
    { "salary": { $gt: 4000000 } }
  ]
})

// AND + OR combinados: clientes de Peru que sean de Accounting o Sales
db.clientes.find({
  "country": "Peru",
  $or: [
    { "department": "Accounting" },
    { "department": "Sales" }
  ]
})

$or va al mismo nivel que los demás campos del objeto de consulta. Se puede combinar con condiciones directas: las condiciones directas siguen siendo AND, y el $or agrega la disyunción sobre su arreglo interno.

Comando

Read — Operadores lógicos

find con $and

MongoDB Shell 
// AND implícito (forma habitual — equivalente al $and explícito)
db.clientes.find({
  "country": "Peru",
  "is_active": true
})

// $and explícito — necesario cuando hay dos condiciones sobre el mismo campo
db.clientes.find({
  $and: [
    { "company": { $regex: "^P", $options: "i" } },
    { "company": { $regex: "bug", $options: "i" } }
  ]
})

El AND implícito cubre la mayoría de los casos. El $and explícito es necesario cuando necesitas aplicar dos condiciones distintas sobre el mismo campo (aquí, company debe cumplir ambos patrones a la vez), ya que un objeto JSON no puede tener dos claves iguales.

Comando

Read — Operadores lógicos

find con $not y $nor

MongoDB Shell 
// $not: clientes cuyo salary NO supere 3.000.000
db.clientes.find({
  "salary": { $not: { $gt: 3000000 } }
})

// $nor: clientes que NO sean de Peru NI tengan salary mayor a 4.000.000
// (ninguna de las dos condiciones se cumple)
db.clientes.find({
  $nor: [
    { "country": "Peru" },
    { "salary": { $gt: 4000000 } }
  ]
})

$not envuelve un operador sobre un campo y devuelve los documentos donde esa condición no se cumple. $nor es el inverso de $or: devuelve los documentos donde ninguna de las condiciones del arreglo se cumple.

Concepto

Read — Fechas

Filtros
de fecha

MongoDB almacena fechas con el tipo Date (BSON). Para consultarlas usamos ISODate("YYYY-MM-DD"), que es la forma estándar de representar una fecha en el shell.

Los mismos operadores de comparación ($gte, $lte) funcionan con fechas exactamente igual que con números, lo que permite construir rangos de fechas de forma directa.

📅
Uso real

Clientes que ingresaron en junio, registros creados este año, historial del último trimestre: todos se construyen con un rango $gte / $lte sobre un campo fecha.

Comando

Read — Fechas

find con ISODate

MongoDB Shell 
// Clientes con start_date en junio 2025
db.clientes.find({
  "start_date": {
    $gte: ISODate("2025-06-01"),
    $lte: ISODate("2025-06-30")
  }
})

// Clientes de junio 2025 con salary mayor a 2.000.000
db.clientes.find({
  "start_date": {
    $gte: ISODate("2025-06-01"),
    $lte: ISODate("2025-06-30")
  },
  "salary": { $gt: 2000000 }
})

ISODate() convierte el string en un objeto Date de BSON. La estructura del rango es idéntica al rango numérico que ya vimos: el campo tiene un objeto con $gte y $lte al mismo tiempo.

Concepto

Read — Texto

Búsqueda
con $regex

El operador $regex permite buscar documentos donde un campo de texto contenga, empiece o termine con un patrón, en lugar de requerir una coincidencia exacta.

La opción $options: "i" hace la búsqueda insensible a mayúsculas, que es el comportamiento esperado en cualquier campo de búsqueda de una aplicación real.

🔍
Cuándo usarlo

Buscadores por nombre, filtros de texto libre, validar que un campo contiene cierta palabra — cualquier "buscar mientras escribes" usa regex por debajo.

Comando

Read — Texto

find con $regex

MongoDB Shell 
// Clientes cuya empresa contenga "bug" (sin importar mayúsculas)
db.clientes.find({
  "company": { $regex: "bug", $options: "i" }
})

// Clientes cuyo nombre empiece con "A"
db.clientes.find({
  "first_name": { $regex: "^A", $options: "i" }
})

// Clientes de empresa con "bug" y salary mayor a 2.000.000
db.clientes.find({
  "company": { $regex: "bug", $options: "i" },
  "salary": { $gt: 2000000 }
})

El ^ al inicio ancla el patrón al comienzo del string. Sin él, busca el patrón en cualquier posición del texto. $options: "i" desactiva la distinción mayúscula/minúscula. Funciona igual sobre cualquier campo de texto: company, first_name, city, etc.

Concepto

Read — Ordenar y paginar

.sort()
y .limit()

find() devuelve documentos en orden arbitrario y sin límite de cantidad. Para controlar el resultado se encadenan métodos directamente sobre el cursor:

  • .sort({ campo: 1 }) ordena ascendente (menor a mayor).
  • .sort({ campo: -1 }) ordena descendente (mayor a menor).
  • .limit(n) devuelve solo los primeros n documentos.
📊
Uso real

"Los 10 clientes con mayor salary", "los últimos 5 registros ingresados", "clientes ordenados por balance" — todos combinan sort + limit.

Comando

Read — Ordenar y paginar

.sort() y .limit()

MongoDB Shell 
// Los 5 clientes con mayor salary
db.clientes.find({})
  .sort({ "salary": -1 })
  .limit(5)

// Clientes de junio 2025 ordenados de más antiguo a más reciente
db.clientes.find({
  "start_date": {
    $gte: ISODate("2025-06-01"),
    $lte: ISODate("2025-06-30")
  }
}).sort({ "start_date": 1 })

// Top 3 clientes del departamento Accounting con mayor balance
db.clientes.find({ "department": "Accounting" })
  .sort({ "balance": -1 })
  .limit(3)

Los métodos se encadenan después de find() en cualquier orden, pero la convención es .sort() primero y .limit() después. MongoDB aplica el sort antes del limit internamente, sin importar el orden escrito.

Concepto

Read — Existencia de campos

$exists

En MongoDB, los documentos de una misma colección no tienen que tener los mismos campos. Un documento puede tener un campo avatar y otro no. $exists permite filtrar según si un campo está presente o ausente.

  • $exists: true → el campo existe en el documento.
  • $exists: false → el campo no existe en el documento.
💡
Por qué importa

En SQL todos los campos siempre existen (con NULL si no tienen valor). En MongoDB la ausencia del campo es diferente a tener el campo con valor null. $exists es específico del modelo documental.

Comando

Read — Existencia de campos

find con $exists

MongoDB Shell 
// Clientes que tienen el campo "avatar" registrado
db.clientes.find({
  "avatar": { $exists: true }
})

// Clientes que NO tienen el campo "avatar" (campo ausente)
db.clientes.find({
  "avatar": { $exists: false }
})

// Combinar con otros operadores: clientes con balance registrado mayor a 3.000.000
db.clientes.find({
  "balance": { $exists: true, $gt: 3000000 }
})

$exists se puede combinar con otros operadores sobre el mismo campo. En el tercer ejemplo, el campo debe existir y además superar el valor 10.

Concepto

Read — Contar resultados

.countDocuments()

find() devuelve los documentos completos. Cuando solo necesitamos cuántos documentos cumplen una condición, usamos .countDocuments() directamente con el filtro.

Acepta el mismo objeto de consulta que find(): sin filtro cuenta todos los documentos de la colección; con filtro cuenta solo los que coinciden.

📊
Uso real

"¿Cuántos clientes hay en el departamento Sales?", "¿cuántos tienen salary mayor a 3 millones?", "¿cuántos registros no tienen el campo avatar?" — todas son preguntas de conteo.

Comando

Read — Contar resultados

.countDocuments()

MongoDB Shell 
// Cuántos documentos hay en total en la colección
db.clientes.countDocuments({})

// Cuántos clientes pertenecen al departamento "Sales"
db.clientes.countDocuments({ "department": "Sales" })

// Cuántos clientes de junio 2025 tienen salary mayor a 2.000.000
db.clientes.countDocuments({
  "start_date": {
    $gte: ISODate("2025-06-01"),
    $lte: ISODate("2025-06-30")
  },
  "salary": { $gt: 2000000 }
})

A diferencia de .sort() y .limit(), .countDocuments() recibe el filtro como argumento directo, no se encadena sobre find(). Devuelve un número, no un cursor.

Bloque 02

Actualizar
documentos

Modificar datos existentes sin tener que reinsertarlos. MongoDB permite actualizar un campo específico sin tocar el resto del documento.

Concepto

Update

updateOne
vs updateMany

Ambos comandos reciben dos argumentos: el filtro que identifica qué documentos modificar, y el operador de actualización que describe el cambio.

updateOne
updateOne({ filtro }, { $set })

Modifica el primer documento que coincida con el filtro. Aunque haya 10 coincidencias, solo toca la primera.

updateMany
updateMany({ filtro }, { $set })

Modifica todos los documentos que coincidan con el filtro. Ideal para cambios masivos (precios, categorías, estados).

⚠️
El operador $set es obligatorio

Si no usas $set y pasas directamente el objeto con los nuevos valores, MongoDB reemplaza todo el documento y pierdes los demás campos.

Comando

Update

updateOne con $set

MongoDB Shell 
// Cambiar el salary de un cliente específico
db.clientes.updateOne(
  { "id": 1 },                          // filtro: qué documento
  { $set: { "salary": 5000000 } }       // qué cambiar
)

// Agregar un campo nuevo sin borrar los existentes
db.clientes.updateOne(
  { "id": 1 },
  { $set: {
      "salary": 5000000,
      "notas": "Salario actualizado por revisión anual"
    }
  }
)

// Verificar el resultado
db.clientes.find({ "id": 1 })

$set solo modifica los campos que se le indican. Los demás campos del documento quedan intactos. Si el campo no existe, lo crea.

Comando

Update

updateMany — cambio masivo

MongoDB Shell 
// Marcar como premium todos los clientes del departamento Accounting
// (campo nuevo: clasificación de clientes)
db.clientes.updateMany(
  { "department": "Accounting" },
  { $set: { "premium": true } }
)

// Actualizar currency en todos los clientes de Peru
db.clientes.updateMany(
  { "country": "Peru" },
  { $set: { "currency": "USD" } }
)

// Verificar cuántos documentos tienen el campo premium
db.clientes.countDocuments({ "premium": true })

El shell devuelve un objeto con matchedCount (cuántos coincidieron) y modifiedCount (cuántos fueron realmente cambiados). Si ya tenían ese valor, modifiedCount puede ser menor que matchedCount.

Resultado

Update — Respuesta del shell

Qué devuelve updateMany

Output — IntelliShell
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 4,      // cuántos documentos coincidieron
  modifiedCount: 4,     // cuántos fueron efectivamente cambiados
  upsertedCount: 0
}

Hábito recomendado: siempre verificar con un find() después del update para confirmar que el cambio quedó como esperabas.

Bloque 03

Eliminar
con precisión

Ya conocemos deleteMany({}) que borra todo. Ahora aprendemos a eliminar con condición para borrar exactamente lo que queremos.

Concepto

Delete

deleteOne
vs deleteMany

deleteOne
deleteOne({ filtro })

Elimina el primer documento que coincida. Seguro cuando sabemos que el filtro identifica exactamente un registro (por ID).

deleteMany
deleteMany({ filtro })

Elimina todos los documentos que coincidan. El {} sin filtro borra la colección completa — usar con mucho cuidado.

🚫
No hay papelera de reciclaje

En MongoDB, los documentos eliminados no se pueden recuperar. Siempre ejecuta primero un find() con el mismo filtro para confirmar qué documentos vas a borrar.

Comando

Delete con filtro

deleteOne y deleteMany

MongoDB Shell 
// PASO 1: Verificar qué vamos a borrar (siempre primero)
db.clientes.find({ "id": 3 })

// PASO 2: Eliminar solo ese documento
db.clientes.deleteOne({ "id": 3 })


// Eliminar todos los clientes con salary menor a 1.000.000
db.clientes.find({ "salary": { $lt: 1000000 } })    // verificar
db.clientes.deleteMany({ "salary": { $lt: 1000000 } }) // ejecutar


// Confirmar que quedaron los correctos
db.clientes.countDocuments({})

La secuencia find → delete es un hábito de trabajo profesional. Nunca ejecutar un delete directamente sin antes ver qué documentos afecta.

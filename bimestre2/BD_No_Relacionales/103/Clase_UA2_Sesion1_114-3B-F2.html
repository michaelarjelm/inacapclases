01 — Conexión
Bloque 01
Conexión a Atlas
desde Studio3T

MongoDB Atlas es la nube donde vive tu base de datos. Studio3T es la herramienta que usamos para conectarnos y trabajar con ella desde tu computador.

Concepto
01 — Conexión · ¿Qué es cada cosa?
Atlas y Studio3T:
¿cuál hace qué?

MongoDB Atlas es una plataforma en la nube donde vive tu base de datos. Tus datos se guardan en servidores de MongoDB en internet, no en tu computador. Ya creaste una cuenta y un clúster (un servidor) en clases anteriores.

Studio3T Community es una aplicación que instalaste en tu computador. Su función es conectarse a ese servidor en la nube y permitirte ver, insertar, modificar y eliminar datos usando una interfaz gráfica y un shell de comandos.

La relación es simple: Atlas guarda los datos, Studio3T te permite trabajar con ellos. Sin conexión a Atlas, Studio3T no tiene nada que mostrar.

💡
Analogía

Atlas es como un servidor de correo (Gmail). Studio3T es como un cliente de correo (Outlook). El correo vive en el servidor; el cliente solo te da una interfaz para leerlo y escribirlo.

Concepto
01 — Conexión · Pasos para conectar
Cómo conectar
Studio3T a Atlas

Si ya tienes la conexión guardada de sesiones anteriores, solo haz doble clic sobre ella en el panel izquierdo de Studio3T. Si no aparece, sigue estos pasos:

  • Paso 1: Abre Studio3T. En la barra superior haz clic en Connect.
  • Paso 2: Selecciona New Connection.
  • Paso 3: En el campo From URI, pega tu connection string de Atlas. Tiene este formato:
    mongodb+srv://usuario:contraseña@cluster0.xxxxx.mongodb.net/
  • Paso 4: Haz clic en Test connection. Debe aparecer un mensaje verde de éxito.
  • Paso 5: Haz clic en Save & Connect.
✓
Señal de conexión exitosa

El panel izquierdo de Studio3T muestra el nombre de tu clúster con un ícono de servidor y las bases de datos disponibles debajo.

⚠
Si no conecta

Verifica que tu IP esté en la lista blanca de Atlas. En Atlas: Network Access → Add IP Address → Add Current IP Address.

02 — Estructura
Bloque 02
Bases de datos
y colecciones

Antes de guardar cualquier dato, necesitamos entender cómo MongoDB organiza la información y crear el espacio donde vamos a trabajar.

Concepto
02 — Estructura · Organización de MongoDB
¿Cómo organiza
MongoDB los datos?

MongoDB organiza la información en tres niveles, de mayor a menor:

  • Base de datos: el contenedor más grande. Agrupa colecciones relacionadas entre sí. Por ejemplo, una base de datos llamada ventas_restaurante contiene todo lo relacionado con ese negocio.
  • Colección: equivale a una tabla en SQL, pero sin estructura fija. Es un conjunto de documentos del mismo tema. Por ejemplo, la colección ventas contiene los registros de venta.
  • Documento: el equivalente a una fila en SQL, pero en formato JSON. Cada documento es un registro individual. Por ejemplo, una venta específica.
💡
Comparación con SQL

Base de datos → Base de datos  |  Colección → Tabla  |  Documento → Fila  |  Campo → Columna

Comando
02 — Estructura · Seleccionar base de datos
Comando: use
IntelliShell — Studio3T 
// Selecciona la base de datos con la que vas a trabajar.
// Si no existe, MongoDB la crea automáticamente
// cuando insertas el primer documento.

use ventas_restaurante

use le dice a MongoDB: "a partir de ahora, todos los comandos que escriba los ejecuto sobre esta base de datos". Es como cambiar de carpeta en el sistema de archivos.

Nota importante: la base de datos no se crea físicamente en este momento. MongoDB espera a que insertes al menos un documento antes de crearla de verdad. Esto es intencional: MongoDB no crea estructuras vacías.

Resultado
02 — Estructura · Resultado de use
Qué devuelve use
Resultado en IntelliShell
switched to db ventas_restaurante

El mensaje switched to db ventas_restaurante confirma que ahora estás trabajando dentro de esa base de datos. Todos los comandos que escribas a continuación (como db.ventas.find()) se ejecutarán sobre ventas_restaurante.

En Studio3T, también puedes ver en la barra inferior o en el panel izquierdo cuál es la base de datos activa en este momento.

Comando
02 — Estructura · Crear colección
Comando: createCollection()
IntelliShell — Studio3T 
// Crea la colección "ventas" dentro de la base de datos activa.
// Ejecutar DESPUÉS de haber usado "use ventas_restaurante".

db.createCollection("ventas")

db siempre hace referencia a la base de datos activa (la que seleccionamos con use). createCollection() crea una colección vacía con el nombre que le indiques entre comillas.

Esto es útil para que la colección aparezca visible en el panel izquierdo de Studio3T antes de insertar el primer documento. También te permite verificar que estás trabajando en el lugar correcto.

Resultado
02 — Estructura · Resultado de createCollection()
Qué devuelve createCollection()
Resultado en IntelliShell
{ ok: 1 }

ok: 1 significa que la operación fue exitosa. En MongoDB, 1 equivale a "sí" o "verdadero" en este contexto.

Después de ejecutar este comando, ve al panel izquierdo de Studio3T, haz clic derecho sobre tu clúster y selecciona Refresh. Deberías ver la base de datos ventas_restaurante con la colección ventas dentro.

✓
Si no aparece en el panel

Haz clic derecho sobre el nombre del clúster en el panel izquierdo y selecciona Refresh. Studio3T no actualiza el panel automáticamente.

03 — Documentos
Bloque 03
Anatomía de
un documento

Un documento es la unidad básica de información en MongoDB. Antes de insertar el primero, necesitamos entender exactamente cómo está construido.

Concepto
03 — Documentos · Qué es un documento
¿Qué es un
documento MongoDB?

Un documento es un objeto en formato JSON (JavaScript Object Notation). Es simplemente un conjunto de pares campo: valor encerrados entre llaves { }.

Cada par campo-valor representa una característica del objeto que estás guardando. Por ejemplo, para guardar una venta de un restaurante, tendríamos campos como el nombre del restaurante, el producto vendido, el precio, etc.

  • Los campos son los nombres de los atributos. Van entre comillas dobles: "Restaurante"
  • Los valores pueden ser texto, números, fechas, booleanos, entre otros.
  • Cada par campo-valor se separa del siguiente con una coma.
  • El último par no lleva coma.
💡
A diferencia de SQL

En SQL, todas las filas tienen exactamente las mismas columnas. En MongoDB, dos documentos de la misma colección pueden tener campos diferentes. Esta flexibilidad es una de las grandes ventajas del modelo documental.

04 — _id
Bloque 04
El campo _id
y ObjectId

Cada vez que insertes un documento, MongoDB va a agregar un campo que tú no escribiste. Es el más importante de todos y aparecerá en cada operación que hagas.

Concepto
04 — _id · Identificador único
¿Qué es el campo _id?

El campo _id es el identificador único de cada documento dentro de una colección. MongoDB lo agrega automáticamente cuando insertas un documento, aunque tú no lo escribas.

Su función es garantizar que cada documento sea identificable de forma única e inequívoca. No pueden existir dos documentos con el mismo _id en la misma colección.

Es el equivalente directo de la clave primaria (PRIMARY KEY) en una base de datos relacional como SQL. Sin embargo, en MongoDB no necesitas declararlo: existe siempre, en todo documento, sin excepción.

⚠
Nunca ignores el _id

Siempre que veas un resultado en MongoDB, el campo _id aparecerá primero. No es ruido del sistema: es el identificador que usarás para buscar, actualizar y eliminar documentos de forma precisa.

Concepto
04 — _id · Qué es ObjectId
¿Qué es ObjectId?

Cuando insertas un documento sin definir un _id, MongoDB genera automáticamente un valor de tipo ObjectId. Se ve así:

ObjectId('6831f4a2e3c89b4d1f20aa01')

Es una cadena de 24 caracteres hexadecimales (números del 0 al 9 y letras de la a a la f). No es aleatoria: está construida con:

  • 4 bytes: timestamp del momento exacto en que se generó
  • 5 bytes: identificador único del proceso que lo creó
  • 3 bytes: contador incremental

Esto garantiza que dos ObjectId generados en el mismo instante, en distintos servidores del mundo, nunca serán iguales. Es una propiedad crucial para bases de datos distribuidas.

✓
¿Puedo definir mi propio _id?

Sí. Puedes asignar cualquier valor único como _id, incluyendo un número entero. En esta unidad dejaremos que MongoDB lo genere automáticamente.

05 — Tipos
Bloque 05
Tipos de datos
en MongoDB

El tipo de dato que uses para cada campo determina cómo MongoDB lo guarda y cómo puedes consultarlo. Usar el tipo incorrecto genera errores difíciles de detectar.

Referencia
05 — Tipos · Tabla de referencia
Tipos de datos
más importantes
Tipo Ejemplo en el documento Cuándo usarlo
String "Liguria Lastarria" Texto. Nombre, descripción, código, dirección.
Integer 5   19 Números enteros. Mesa, cantidad, minutos.
Double 9200   874 Números decimales o con cálculos. Precios, totales.
Boolean true   false Verdadero o falso. Sin comillas, en minúscula.
Date ISODate("2026-01-05T16:10:00.000Z") Fecha y hora. Permite comparaciones y ordenamiento.
Null null Ausencia explícita de valor. Distinto a campo no existente.
Array ["Lunes", "Martes"] Lista de valores. Lo veremos en profundidad más adelante.
Object { "clave": "valor" } Documento anidado (subdocumento). También más adelante.
ObjectId ObjectId('6831f4...') Identificador único generado por MongoDB. Tipo del _id.
⚠
El tipo importa siempre

"9200" (string) y 9200 (número) son valores distintos en MongoDB. Si guardas un precio como texto, no podrás hacer comparaciones como "mayor que" o "menor que" correctamente.

06 — Insert
Bloque 06
insertOne
insertMany

Estos son los dos comandos para agregar documentos a una colección. Uno inserta un documento a la vez, el otro inserta varios en una sola operación.

Concepto
06 — Insert · ¿Qué hace insertOne?
¿Qué hace
insertOne()?

insertOne() inserta exactamente un documento en la colección. El documento que quieres guardar se pasa como argumento entre los paréntesis, con toda la estructura JSON que vimos antes.

La sintaxis general es:

db.nombreColeccion.insertOne({ campo: valor, campo: valor, ... })

  • db siempre hace referencia a la base de datos activa (la que seleccionamos con use).
  • nombreColeccion es el nombre de la colección donde quieres insertar. En nuestro caso: ventas.
  • insertOne() recibe el documento completo entre sus paréntesis.
💡
No necesitas declarar los campos antes

A diferencia de SQL donde primero se define la tabla con sus columnas, en MongoDB simplemente insertas el documento. La colección acepta cualquier estructura.

Concepto
06 — Insert · ¿Qué hace insertMany?
¿Qué hace
insertMany()?

insertMany() inserta múltiples documentos en una sola operación. En lugar de un documento, recibe un arreglo de documentos: una lista encerrada entre corchetes [ ] donde cada documento va separado por una coma.

La sintaxis general es:

db.nombreColeccion.insertMany([ {doc1}, {doc2}, {doc3} ])

  • Los corchetes [ ] delimitan el arreglo completo.
  • Cada documento va entre llaves { } separado por coma del siguiente.
  • El último documento no lleva coma después de su llave de cierre }.
✓
¿Por qué usar insertMany en vez de varios insertOne?

Una sola operación de red es mucho más eficiente que ocho operaciones separadas. Para cargar un dataset inicial, siempre se prefiere insertMany.

⚠
Antes de ejecutar insertMany: limpiar la colección

Ya insertaste un documento con insertOne. Para evitar duplicados, primero ejecuta: db.ventas.deleteMany({}) — esto elimina todos los documentos de la colección.

acknowledged: true confirma que la operación fue exitosa. insertedIds muestra el _id generado para cada documento, indexados por su posición en el arreglo: '0' es el primer documento, '1' el segundo, y así sucesivamente.

Los ObjectId que verás en tu pantalla serán diferentes a los del ejemplo porque MongoDB los genera en el momento exacto de la inserción.

07 — Consulta
Bloque 07
find()
y findOne()

Después de insertar documentos, necesitas poder verlos. Estos dos comandos son los más básicos para recuperar información de una colección.

Concepto
07 — Consulta · Diferencia entre find y findOne
find() vs findOne():
¿cuál usar?

find() devuelve todos los documentos que existan en la colección. Si tienes 8 documentos, los devuelve todos. Es el equivalente de SELECT * FROM tabla en SQL.

findOne() devuelve solo el primer documento que encuentre, sin importar cuántos haya. Es útil para verificar rápidamente la estructura de los documentos sin traer toda la colección.

  • Ambos comandos reciben un filtro como argumento. Sin filtro (o con {}), no aplican ninguna condición.
  • En las próximas sesiones aprenderemos a agregar filtros para buscar documentos específicos.
  • Por ahora los usamos sin filtro para ver todo lo que guardamos.
💡
¿Qué es un cursor?

find() no devuelve los documentos directamente sino un cursor: un puntero que apunta al resultado. Studio3T lo recorre automáticamente y te muestra los documentos. En Python, deberás iterar sobre ese cursor con un for. Lo veremos más adelante en la unidad.

Comando
07 — Consulta · find() y findOne()
Comandos: find() y findOne()
IntelliShell — Studio3T 
// Devuelve TODOS los documentos de la colección ventas
db.ventas.find({})

// Devuelve solo el PRIMER documento que encuentre
db.ventas.findOne({})

El argumento {} entre los paréntesis es el filtro vacío: le dice a MongoDB "tráeme documentos sin ninguna condición". Es como decir "dame todo".

Para ejecutar solo una de las dos líneas, selecciona esa línea antes de presionar Ctrl + Enter. De lo contrario, Studio3T ejecutará ambas.

08 — Verificación
Bloque 08
countDocuments()

Después de cualquier operación, lo primero que debes preguntarte es: ¿quedaron los documentos que esperaba? Este comando responde esa pregunta en una línea.

Concepto
08 — Verificación · Por qué contar siempre
¿Por qué usar
countDocuments()?

countDocuments() devuelve el número de documentos que hay en una colección. No muestra los documentos, solo cuenta cuántos existen.

Este comando es tu herramienta principal de verificación. Después de un insertMany con 8 documentos, lo primero que debes hacer es ejecutar countDocuments({}) y confirmar que el resultado es 8. Si el número es distinto, algo salió mal.

⚠
Instala este hábito desde hoy

En bases de datos relacionales, los errores suelen ser visibles (la query falla con un error). En MongoDB, es posible insertar documentos con estructura incorrecta sin que aparezca ningún error. countDocuments() es tu primera línea de defensa.

El argumento {} significa "sin filtro": cuenta todos los documentos de la colección. En sesiones futuras aprenderás a pasarle un filtro para contar solo los que cumplen una condición específica.

Comando
08 — Verificación · countDocuments()
Comando: countDocuments()
IntelliShell — Studio3T 
// Cuenta todos los documentos de la colección
db.ventas.countDocuments({})

// Adelanto: también puedes contar con filtro (lo veremos la próxima sesión)
// db.ventas.countDocuments({ "Restaurante": "El Hoyo" })

Ejecuta este comando inmediatamente después de haber corrido el insertMany. El resultado debe ser 8.

Resultado
08 — Verificación · Resultado de countDocuments()
Qué devuelve countDocuments({})
Resultado en IntelliShell
8

Un número simple. En este caso 8, que confirma que los ocho documentos del dataset se insertaron correctamente.

Si el resultado fuera 9, significaría que el documento que insertaste con insertOne al principio de la sesión sigue ahí y se duplicó. En ese caso, ejecuta db.ventas.deleteMany({}) y vuelve a correr el insertMany.

✓
Patrón que usarás toda la unidad

insert → countDocuments({}) → verificar número → continuar. Si el número no es el esperado, detente y revisa antes de seguir.

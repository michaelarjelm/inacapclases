Consulta parametrizada
Una consulta que usa marcadores ? en vez de pegar los valores dentro del texto del SQL. Los valores se entregan por separado, y la librería garantiza que nunca se interpretan como código SQL.

Inyección SQL
Un ataque donde alguien aprovecha que el SQL se armó pegando texto, para meter su propio pedazo de SQL disfrazado de dato.

Así se vería eliminar() de AutoDAO si se escribiera con f-string:

nunca así
self.cursor.execute(f"DELETE FROM autos WHERE patente = '{patente}'")

Si en vez de una patente alguien escribe esto:

lo que llega como patente
' OR '1'='1
el SQL que arma el f-string
DELETE FROM autos WHERE patente = '' OR '1'='1'
resultado
autos antes: 2
autos después: 0
●
'1'='1' es verdadero para todas las filas

El WHERE deja de filtrar y el DELETE borra la tabla completa. Nadie hackeó nada: solo escribieron texto en el lugar de la patente.

La solución
El mismo texto, con el marcador
Con ?, el ataque
es solo texto
dao/auto_dao.py · como se escribe de verdad
self.cursor.execute("DELETE FROM autos WHERE patente = ?", (patente,))
mismo texto: ' OR '1'='1
autos antes: 2
autos después: 2

Y no hace falta un atacante para que el f-string falle. Basta una marca con comilla:

Nunca
f"...WHERE patente = '{p}'"
Siempre

El ? no filtra caracteres peligrosos

Nunca los interpreta como código. Todo lo que entra por el marcador es un valor, tenga lo que tenga adentro.

Definición

y listar()
SELECT
El comando SQL que lee filas de una tabla, con o sin condición.
dao/marca_dao.py · dos métodos nuevos
from dao.dao import DAO
from model.marca import Marca

    def buscar(self, id):
        self.cursor.execute("SELECT id, nombre FROM marcas WHERE id = ?", (id,))
        fila = self.cursor.fetchone()
        if fila is None:
            return None
        marca = Marca(fila[1])
        marca.id = fila[0]
        return marca

    def listar(self):
        self.cursor.execute("SELECT id, nombre FROM marcas")
        marcas = []
        for fila in self.cursor.fetchall():
            marca = Marca(fila[1])
            marca.id = fila[0]
            marcas.append(marca)
        return marcas
Método del cursorDevuelve
fetchone()Una fila como tupla, o None si no encontró nada
fetchall()Una lista con todas las filas
lo que devuelve cada llamada
marca_dao.buscar(1)   -> Marca, nombre Toyota
marca_dao.buscar(99)  -> None
marca_dao.listar()    -> [(1, Toyota), (2, Honda)]
●
El DAO devuelve objetos, no tuplas

fila[0] y fila[1] se usan solo adentro del DAO. main.py recibe una Marca y usa marca.nombre, sin saber en qué posición venía cada columna.

JOIN
Une las filas de dos tablas usando la FOREIGN KEY. Así, en una sola consulta llega el modelo junto con los datos de su marca.

    def buscar(self, id):
        self.cursor.execute("""
            SELECT modelos.id, modelos.nombre, marcas.id, marcas.nombre
            FROM modelos
            JOIN marcas ON marcas.id = modelos.marca_id
            WHERE modelos.id = ?
        """, (id,))
        fila = self.cursor.fetchone()
        if fila is None:
            return None
        marca = Marca(fila[3])
        marca.id = fila[2]
        modelo = Modelo(fila[1], marca)
        modelo.id = fila[0]
        return modelo

Auto
Cuatro tablas en una consulta
AutoDAO
buscar()
dao/auto_dao.py
    def buscar(self, patente):
        self.cursor.execute("""
            SELECT vehiculos.patente, vehiculos.anio, vehiculos.en_taller,
                   modelos.id, modelos.nombre, marcas.id, marcas.nombre
            FROM autos
            JOIN vehiculos ON vehiculos.patente = autos.patente
            JOIN modelos ON modelos.id = vehiculos.modelo_id
            JOIN marcas ON marcas.id = modelos.marca_id
            WHERE autos.patente = ?
        """, (patente,))
        fila = self.cursor.fetchone()
        if fila is None:
            return None
        marca = Marca(fila[6])
        marca.id = fila[5]
        modelo = Modelo(fila[4], marca)
        modelo.id = fila[3]
        auto = Auto(fila[0], fila[1], modelo)
        if fila[2]:
            auto.ingresar()
        return auto

Parte desde autos: siempre devuelve un Auto

en_taller no tiene setter: el objeto solo cambia de estado con sus propios métodos. El DAO respeta el encapsulamiento y usa el mismo camino que usaría cualquier otra parte del programa.

Transacciones:
todo o nada

Guardar un auto toca tres DAO. Si uno falla, no puede quedar la mitad guardada.

Definición
Por qué los DAO no hacen commit()
commit(), rollback()
y close()
Transacción
Un conjunto de operaciones que se tratan como una sola unidad: o se guardan todas, o no se guarda ninguna.
main.py
from conectar import crear_conexion
from model.marca import Marca
from model.modelo import Modelo
from model.auto import Auto
from dao.marca_dao import MarcaDAO
from dao.modelo_dao import ModeloDAO
from dao.auto_dao import AutoDAO

conexion = crear_conexion()
marca_dao = MarcaDAO(conexion)
modelo_dao = ModeloDAO(conexion)
auto_dao = AutoDAO(conexion)

marca_dao.crear_tabla()
modelo_dao.crear_tabla()
auto_dao.crear_tabla()
conexion.commit()

try:
    toyota = Marca("Toyota")
    marca_dao.insertar(toyota)

    yaris = Modelo("Yaris", toyota)
    modelo_dao.insertar(yaris)

    auto = Auto("AB1234", 2018, yaris)
    auto_dao.insertar(auto)

    conexion.commit()
    print("Auto guardado con su modelo y su marca.")
except Exception as error:
    conexion.rollback()
    print("No se guardó nada:", error)
finally:
    conexion.close()
salida · ejecutado dos veces
$ python main.py
Auto guardado con su modelo y su marca.
$ python main.py
No se guardó nada: UNIQUE constraint failed: vehiculos.patente
MétodoQué hace
commit()Confirma todo lo ejecutado desde el último commit
rollback()Deshace todo lo que no se confirmó
close()Cierra la conexión. En finally, se cierra aunque algo haya fallado
●
La segunda vez no quedó ni la marca ni el modelo repetidos

La patente AB1234 ya existía, así que el tercer INSERT falló. El rollback() deshizo también la marca y el modelo que se habían insertado en esa misma ejecución.

Cuidado
Un error a mitad de camino
La base se deshace,
la memoria no

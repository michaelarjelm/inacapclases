Qué es una
base de datos

Y por qué, para este proyecto, vamos a usar la más simple que existe.

Definición
Antes de tocar código
Base de datos

Base de datos
Un lugar organizado donde se guarda información de forma permanente, en disco, no en la memoria RAM del programa. Sobrevive aunque el programa se cierre.
Para el taller: los clientes, los vehículos, las órdenes de trabajo y los repuestos.
Motor de base de datos · sistema gestor
El programa que administra la base de datos: la crea, guarda la información ahí, la protege, y responde cuando alguien la consulta.
MySQL, PostgreSQL y SQLite son motores de base de datos distintos.
MySQL / PostgreSQLSQLite
Cómo se instalaUn servidor aparte, hay que instalarlo y configurarloViene incluido en Python, no se instala nada
Dónde vive la informaciónEn un servidor que puede estar en otro computadorEn un solo archivo, en el mismo computador
Para qué se usa normalmenteSistemas grandes, con muchos usuarios a la vezProyectos pequeños y medianos, como este
●
Por qué SQLite para este proyecto

No necesitan instalar ni configurar un servidor. Toda su base de datos va a ser un solo archivo, por ejemplo taller.db, que se guarda junto al resto de su código. Es la opción correcta cuando el sistema es de este tamaño.

Definición
El lenguaje de las bases de datos
¿Qué es
SQL?
SQL · Structured Query Language
El lenguaje que se usa para hablarle a una base de datos: crear tablas, guardar información, buscarla, modificarla o borrarla. No es Python: es su propio lenguaje, y se lo pasan a Python como texto.
CREATE TABLE
El comando SQL que define la estructura de una tabla: cómo se llama, qué columnas tiene, y de qué tipo de dato es cada una.

●
SQLite no tiene un tipo BOOLEAN

Por eso en_taller se guarda como INTEGER: 0 para falso, 1 para verdadero. Cuando lean el dato de vuelta en Python, van a tener que convertirlo de nuevo a True o False.

●
PRIMARY KEY

Marca la columna que identifica a cada fila de forma única: no puede haber dos vehículos con la misma patente. La usan para buscar, actualizar o borrar un registro específico, y la vuelven a ver en la sesión 10 con el CRUD completo.

●
conexion.commit()

Los cambios no quedan guardados de forma permanente hasta que se llama a commit(). Sin esa línea, la tabla podría no quedar realmente creada en el archivo.

El patrón
DAO

Primero la idea. Después ordenamos el proyecto en carpetas, reutilizamos la conexión, y al final cada entidad tiene su propio DAO.

El problema
Antes de la solución
SQL mezclado
por todas partes

Si el código SQL queda repartido dentro de cada método que lo necesita, mezclado con la lógica del negocio, pasan dos cosas: es difícil de mantener, y si algún día cambian de motor de base de datos, hay que revisar el programa entero.

SQL mezclado

Cada clase del negocio (Marca, Auto...) tiene su propio código SQL adentro, repetido y disperso.

Con DAO

Todo el SQL vive en una sola clase por tabla. El resto del programa le pide cosas con nombres simples, sin saber que existe SQL.

Definición
Una clase, una responsabilidad
¿Qué es un
DAO?
DAO · Data Access Object · también llamado Repositorio
Una clase encargada solo de hablar con la base de datos para una tabla específica. El resto del programa le pide cosas mediante métodos con nombres claros, sin tener que escribir SQL directamente.
Es la misma idea de encapsulamiento que vieron en la sesión 7, aplicada a nivel de arquitectura: cada clase se hace cargo de su propia responsabilidad.

Paso 2
El archivo que escribieron a mano en el bloque 02
conectar.py
se reutiliza
Antes

Un script que se ejecuta una vez: conecta, crea un auto, imprime y cierra. Nadie más lo puede usar.

Ahora

Una función que cualquier parte del programa llama cuando necesita la conexión.

conectar.py
import sqlite3

def crear_conexion():
    conexion = sqlite3.connect("taller.db")
    conexion.execute("PRAGMA foreign_keys = ON")
    return conexion
●
El único archivo del proyecto que importa sqlite3

Ni main.py ni los DAO lo necesitan: reciben la conexión ya hecha. Si algún día cambian de motor de base de datos, este es el archivo que se toca.

●
PRAGMA foreign_keys = ON

SQLite no revisa las relaciones entre tablas si no se lo piden. Esta línea lo activa, una sola vez, para toda la conexión. Lo van a necesitar en cuanto una tabla apunte a otra, en el paso 4.

●
¿Y las líneas que creaban el auto?

Se van a main.py. conectar.py ya no crea objetos del negocio: solo entrega la conexión.

Paso 3

Lo que todos
los DAO comparten
dao/dao.py · la clase base
class DAO:
    def __init__(self, conexion):
        self.conexion = conexion
        self.cursor = conexion.cursor()
●
La conexión se recibe, no se crea aquí

DAO no llama a sqlite3.connect(). Recibe la conexión que entrega crear_conexion(), así todos los DAO del programa trabajan sobre la misma, en vez de abrir cada uno la suya.

●
La misma idea que Auto con Vehiculo

En la sesión 7, lo que se repetía entre Auto, Moto y Camion subió a Vehiculo. Aquí pasa lo mismo: guardar la conexión y pedir el cursor se escribe una vez en DAO, y cada DAO hijo solo agrega lo propio.

Paso 4 · Marca
Primero la entidad que no depende de nadie
MarcaDAO,
la base
dao/marca_dao.py
from dao.dao import DAO

class MarcaDAO(DAO):
    def crear_tabla(self):
        self.cursor.execute("""
            CREATE TABLE IF NOT EXISTS marcas (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                nombre TEXT NOT NULL
            )
        """)
●
¿Por qué Marca primero?

Un modelo no existe sin su marca, y un auto no existe sin su modelo. Las tablas se crean en ese mismo orden: primero la que no depende de nadie. SQLite no reclama si se invierte, pero PostgreSQL o MySQL sí dan error.

●
id INTEGER PRIMARY KEY AUTOINCREMENT

Una marca no tiene un dato único propio, como la patente de un auto. Por eso usa un número que la base de datos asigna sola: 1, 2, 3...

●
IF NOT EXISTS

Evita un error si ejecutan el programa dos veces: si la tabla ya está creada, simplemente no hace nada.

Paso 4 · Modelo
Una tabla que apunta a otra
ModeloDAO y la
FOREIGN KEY
FOREIGN KEY · llave foránea
Una columna que guarda la PRIMARY KEY de otra tabla. Con ella, la base de datos sabe que cada modelo pertenece a una marca que existe.
Si Toyota quedó con id 1, el Yaris se guarda con marca_id = 1.
dao/modelo_dao.py
from dao.dao import DAO

class ModeloDAO(DAO):
    def crear_tabla(self):
        self.cursor.execute("""
            CREATE TABLE IF NOT EXISTS modelos (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                nombre TEXT NOT NULL,
                marca_id INTEGER NOT NULL,
                FOREIGN KEY (marca_id) REFERENCES marcas(id)
            )
        """)
●
En Python, un objeto. En la tabla, un número

La clase Modelo guarda un objeto Marca completo. La tabla modelos guarda solo el id de esa marca. Es la misma relación del diagrama, escrita de la forma en que la entiende la base de datos.

Paso 4 · Auto
La herencia también llega a las tablas
VehiculoDAO
y AutoDAO
dao/vehiculo_dao.py · la tabla padre
from dao.dao import DAO

class VehiculoDAO(DAO):
    def crear_tabla(self):
        self.cursor.execute("""
            CREATE TABLE IF NOT EXISTS vehiculos (
                patente TEXT PRIMARY KEY,
                anio INTEGER NOT NULL,
                en_taller INTEGER NOT NULL,
                modelo_id INTEGER NOT NULL,
                FOREIGN KEY (modelo_id) REFERENCES modelos(id)
            )
        """)
dao/auto_dao.py · la tabla hija
from dao.vehiculo_dao import VehiculoDAO

class AutoDAO(VehiculoDAO):
    def crear_tabla(self):
        super().crear_tabla()
        self.cursor.execute("""
            CREATE TABLE IF NOT EXISTS autos (
                patente TEXT,
                PRIMARY KEY (patente),
                FOREIGN KEY (patente) REFERENCES vehiculos(patente)
            )
        """)
●
En autos, patente es PRIMARY KEY y FOREIGN KEY a la vez

La PRIMARY KEY impide que el mismo auto aparezca dos veces. La FOREIGN KEY impide que exista un auto sin su fila en vehiculos: igual que en Python, un Auto no existe sin la parte que hereda de Vehiculo.

●
super().crear_tabla()

Así como el constructor de Auto llama al de Vehiculo, AutoDAO llama al crear_tabla() de VehiculoDAO. La tabla padre queda creada antes que la hija, sin repetir su SQL.

●
El tipo de vehículo lo define la herencia, no una columna de texto

Un auto es una fila en vehiculos más una fila en autos. Moto y Camion siguen el mismo patrón, y la tabla camiones agrega su capacidad_carga.
